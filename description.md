# o: drop the flags that read an argument from a file -- match -f, patch -f, get and list -if-file; $(cat file) says it

An argument that is a document is given as the document. The shell already reads a
file into an argument, so a flag that makes `o` do it is a second spelling of one
thing:

    o m -f match.tony          ->  o m "$(cat match.tony)"
    o patch -f p.tony x.yaml   ->  o patch "$(cat p.tony)" x.yaml
    o get -if-file m.tony x    ->  o get -if "$(cat m.tony)" x

## What goes

- `o match -f` -- MatchConfig.File (cmd/o/configs.go:207), read through getish
  (match.go:102), whose file branch also reads "-" as stdin.
- `o patch -f` -- PatchConfig.File (configs.go:269), through getish (patch.go:92).
- `o get -if-file` and `o list -if-file` -- GetConfig.IfFile and ListConfig.IfFile
  (configs.go:166, :186), through ifPredicate (search.go:47-59), which refuses -if with
  -if-file.

getish becomes a parse of its argument. TestIfAndIfFileAgree (if_test.go:160) goes with
-if-file, and the "-if-file" mention in docs.go:42.

## Docs to follow

- docs/o/o-match.md:76, o-patch.md:61, o-get.md:79, o-list.md:95 -- regenerated by
  `o docs`.
- go-tony/README.md:120-121 (`o patch -f patch.tony manifests.yaml`, and `-r -f`).

Not in scope: operands that ARE files -- the documents `o` reads, diff's two sides, and
`o schema check <schema-file>`. Those are inputs, not arguments read from a file.
