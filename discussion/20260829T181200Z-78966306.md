Not fixed, but no longer on the default path: Storage.scopeOverlay now defaults to OFF, so a scoped read replays the scope's patches and this delete is not lost. EnableScopeOverlay(true) still reaches it.

The measurement that decided the default: over 200 seeded mixed streams the overlay broke 44 standing claims and replay broke none, and all five failures that had been holding TestAScopedWriteIsAStandingClaim back were the overlay's -- two of them this issue.

What has to change before the overlay is default again is how it is BUILT. Deriving a scope layer from two documents cannot record a claim, which is what this issue is; the read path is fine with an overlay it is HANDED. Note also that a scoped read no longer has to replay the whole scope to be fast: narrowSubtreeAt now takes a scope, so a scoped read at a path costs the patches that bear on that path (flat ~40us against a wide read's 6.7ms at 400 scope writes). That removes most of the pressure the overlay existed to relieve.
