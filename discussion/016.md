Both reports fixed: 33c0200 (with 2370382 correcting a false positive I introduced in 3a115bb).

**Named scalar in field position.** `type Op string` in a field generated `ir.FromString(s.Op)` and `s.Op = node.String` — neither compiles. Not caused by the schema work: verified identical at `afacf92~1`, i.e. before any of it. The conversion landed for slice and map elements with item 8 (`generatePrimitiveToIR` casts in every case, for exactly this reason) but the field switch was missed for **string and bool**; int, uint and float already cast. The decode direction converts through the field's own type name, so a cross-package type is qualified (`namedstr.Op(...)`).

**Item 17.** Still reproduced at v0.0.93; fixed. Imports are collected by walking the field types, which answers "does this package appear in the struct definition", not "does the generated code spell it". Rather than predict which emissions need a qualifier — that means mirroring every branch of the generator and keeping it mirrored — the generated body is now parsed and any import whose local name never appears on the left of a selector is dropped. It over-approximates (a local variable named like a package counts), so it keeps an unneeded import rather than dropping a needed one, which is the previous behaviour.

**The false positive I introduced.** 3a115bb let a reference resolve against any name a `.tony` publishes, including `define:` keys, because `schema/base.tony` publishes `ir` that way. Right for a hand-written schema, wrong for a generated one, whose `define:` keys are one struct's field names — a named type `Op` resolved to `!namedstr:op`, pointing at another struct's field. Restricted to hand-written schemas.

Regenerating produced identity conversions only, and no committed package changed its imports, so the prune fired solely on the new fixture. New fixtures: `namedstr` (named string in field and slice position), `namedstrpkg` (cross-package, needing the qualifier), `valueleaf`/`valuehost` (item 17's struct-value shape). Those packages compiling is most of the test; round-trips pin the conversions as value-preserving. I confirmed each fix is load-bearing by reverting it and watching the fixture fail to compile with the original error.
