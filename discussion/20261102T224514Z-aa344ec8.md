## Is Strict needed? What a spawn loses without it

All five asks are built on branch `issue-xxn12a3g` (local, unpushed). Asks 2–5 (bracket depth, `$$[`, `DisableBuiltins`, `Composite`) are small and independent of Strict. Strict is the costly one, and a review of it found three defects on the first pass, so before it goes further: what does a spawn string lose if it stays on lenient lookups?

**What lenient already refuses.** A parent that is absent. `$[subject.value.handoff.summary]` on a subject without `handoff` is an error today (`cannot fetch summary from <nil>`). Only a leaf under a present parent, or an unknown top-level name, renders `null`.

**What a spawn author can write.** `??` catches a nil value and `fail()` exists, so `$[subject.value.handoff.summary ?? fail("no summary")]` refuses on a missing leaf, on a missing parent (the fetch error) and on a written null. The `"x" in a ? a.x : fail()` form in the issue was only needed to tell a written null from an absent field, and for text going into a pull request body a written null is no better than an absent one.

**So lenient loses** nothing at the language level. It costs `?? fail("…")` at every reference where `null` is unacceptable, and an author who forgets it gets a `null` in the body. A discipline cost, not a capability gap.

**What Strict as built costs.** A rewrite of expr's AST (every node kind, the meaning of `??`, `?.`, `in`, callees, `let`), a hand-rolled copy of expr.Compile's pipeline to run it, and a wrinkle: an unknown top-level name is refused by expr's checker at compile time regardless of position, so `$[nosuch ?? "d"]` fails under Strict while `$[a.nosuch ?? "d"]` does not. Fixing that means re-implementing name resolution inside the rewrite. The review also found that Strict recognized only `map[string]any` (other map kinds rendered their zero value), and that the leniency did not reach `in` or the base of `?.`. All fixable; all surface area to keep in step with expr.

**A cheaper option, if the discipline cost is the problem.** An option that refuses a `$[…]` in text whose value is nothing — `RefuseNull`, say: `$[subject.value.handoff.summary]` → `"subject.value.handoff.summary" is nothing`. One check on the result, no AST rewrite. It covers a missing leaf, an unknown name and a written null; `??` still works, since `a ?? "d"` evaluates to `"d"`. It names the expression rather than the segment that stopped the lookup, and does not tell absent from null. For a spawn string neither distinction seems to matter.

Recommendation: drop Strict from this change, ship 2–5 now, and add the null-result refusal only if `?? fail()` per reference proves too much to ask of authors. Over to the filer.
