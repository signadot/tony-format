## M1a + M1b landed (branch issue-wcabztj2)

M1a (commits fb3cd20, 419b521): docd client-facing listener as a transparent logd
proxy. A libctl.LogdSession pointed at docd behaves as if pointed at logd
(switchability proof). Two listeners (client + mount). Race-clean.

M1b (commit 3594400): path-based routing. docd is a logd-backed document server
with controller overlays — base/unmounted paths -> logd; mounted subtrees ->
owning controller. The docd<->controller op channel reuses the logd session
protocol verbatim (MOUNT is the additive prefix), so a controller is a
logd-session-server for its subtree and full match/patch/watch expressivity comes
for free. Added: MountRegistry.LookupPrefix (longest-prefix), MountSession op
routing (id-multiplexed, results/errors/events forwarded), ClientSession router,
libctl Handler/RunController runtime, `unsupported` error code. E2e tests
(race-clean): mounted->controller, base->logd, unsupported-watch relayed,
watch streaming controller->docd->client.

Known limitation -> M2 follow-up: the controller runtime keys watches by path, so
two different clients watching the SAME mounted path on one controller collide.
Correct fix is docd-side watch fan-out (one controller-facing watch per path,
fanned to N clients) — this is the "watch fan-out" already noted under component D.

Not yet done from M1b's original bullet list: txpool is still not wired into the
Server (docd uses a per-client LogdSession for base paths and has no multi-mount
tx path yet) — folds into M2/M3 with transactions.
