## 15. `FromTonyIR` does not dispatch to a value field's codec — the TO direction does

Item 1 fixed dispatch for the encode direction on values. The decode direction still has the
original shape: it dispatches only for POINTER fields.

```go
type fdMap map[string]any
func (m fdMap) ToTonyIR(...) (*ir.Node, error)   { return ir.FromString("S"), nil }
func (m *fdMap) FromTonyIR(n *ir.Node, ...) error { *m = fdMap{"from": "codec"}; return nil }

type fdStruct struct{ V string }
func (s fdStruct) ToTonyIR(...) (*ir.Node, error)   { return ir.FromString("S"), nil }
func (s *fdStruct) FromTonyIR(n *ir.Node, ...) error { s.V = "from-codec"; return nil }
```

`gomap.FromTony([]byte(`{f: "x"}`), &host)` for a host with one field `f`:

| field shape | result |
|---|---|
| top-level `&fdMap` | dispatches — `map[from:codec]` |
| top-level `&fdStruct` | dispatches — `{V:from-codec}` |
| field `fdMap` (value) | **`unmarshal error at f: expected object, got String`** |
| field `*fdMap` | dispatches |
| field `fdStruct` (value) | **`unmarshal error at f: expected object, got String`** |
| field `*fdStruct` | dispatches |

So a type whose codec accepts a scalar spelling — a string address, a tagged number — encodes
correctly and then fails to decode, purely because of how the field is held. The error also
comes from the generic reflection walker rather than the codec, so it describes the shape the
WALKER expected, not the one the type accepts.

Note **generated code gets this right in both directions** — `s.Format.FromTonyIR(fieldNode)`
— so this is reflection-only, and it is the mirror of item 1.

Presumably the same fix: hoist the method check above the pointer branch and use `val.Addr()`
when the field is addressable (which a struct field being decoded into always is).

**Workaround in verse:** `trigger.Condition` is hand-written so its `Subject Match` field is
decoded explicitly. That is one type; the general shape — "a value field whose type has a
custom codec" — is not something a caller can see coming, since the encode direction works.

Two smaller notes from the same session, not worth their own items:

- `omitzero` is inert on a field whose type carries a `codec=custom` codec: a generated
  `Condition` emitted `subject: null` for every charter that names no subject. Same family as
  item 12 (struct-valued fields), and the same fix probably covers both — the emission guard
  needs to run regardless of how the field's value is produced.

- The item-3 diagnostics are genuinely good. `field Config.Format references type
  "FormatConfig", which codegen cannot resolve: annotate that type with a //tony:schemagen=
  or schema= directive (add codec=custom if it has its own ToTonyIR/FromTonyIR), or mark the
  field omit` named the field, the type and all three remedies. That one message is what made
  the charter package's annotation obvious rather than trial and error.
