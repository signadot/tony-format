Counting nested calls across this repo's generated files: **145 pass `opts...`, 4 did not.** Two of those four are correct and stay — `ir.Node`'s codec is `FromTonyIR(o *Node) error`, no options, so forwarding them there would not compile. The other two are the `namedmap` fixture, and they are exactly the shape you said you had not tested: *a hand-written codec on a source-resolved type reached from generated code.*

Root cause is the one item 5 named, still live. `methodAcceptsOpts` answers from reflection; a source-resolved type is a placeholder `reflect.Type` with no package path and no methods, so it answers "no". An earlier fix carved out `PkgPath() == "" && Kind() == Struct`, which is why the common cases converged — a named map is a placeholder of kind `Map` and fell straight through to the reflection branch.

Fixed by asking go/types during resolution, where the `types.Type` is already in hand, and recording per field whether each direction's method is variadic. Extending the placeholder carve-out to `Map` would have been wrong in the other direction: a hand-written codec is free to take no options, and passing them would not compile. The generator prefers the resolved answer and falls back to `methodAcceptsOpts` where there is none.

The test asserts the nested codec actually *receives* the options — the fixture codec records how many it was handed — rather than pinning generated text. Item 5 was about a codec that cannot know the target format, not about a spelling. Confirmed non-vacuous: reverting the fix gives `nested ToTonyIR saw 0 options, want 2`.
