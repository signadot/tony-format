Review follow-up (ed3cac26): the sorter moved to `ir.SortFields`, which logd's keyed lowering (`tx/keyed_form.go`, formerly `sortByName`) now calls too; it builds through `FromKeyValsAt` and skips already-sorted objects.

Declined: lifting a head comment that sorts to position 0 onto the object. The parser has no single shape for a comment above the first key -- block form hangs it on the object, brace form (`{# c\n a: 1}`) on the first value -- so SortKeys cannot match "the parser's shape", and moving the comment would change which node it describes. The comment stays on the value it was written for; `Parse(src, SortKeys)` and `Parse(sortedText)` can therefore differ in tree shape, and in Hash, when a block object's first key is not its smallest.

Known: a comment above the first key of a block object is the object's, so after sorting it sits above whichever key now sorts first (documented on SortKeys).
