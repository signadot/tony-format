From the tony-format side, having read `mergeop` (at, not, get-path), `match.go` and verse's `trigger/match.go` at 7353d0b0.

## Short answer

It fits the vocabulary as it is, as four leaf match ops. There is one design fork (absence) that the tony-format owner decides; it is noted below, with a recommendation.

## How it fits

`!ge(0.8).get-path(root) limit` already parses into the right pieces. `SplitChild` hands the `ge` symbol its args `["0.8"]` and a child that carries the rest of the chain, here the node `limit` tagged `!get-path(root)`. So:

- `!lt`, `!le`, `!gt`, `!ge` are match-only leaf ops. The doc node they meet is the left side.
- **Operand**: a number literal, or `!get-path` / `!get-path(root)` naming one node. The op evaluates that itself, with the same fetch `!get-path` uses. Anything else is refused when the pattern is built. It is not handed to the match function, because the operand is a value, not a pattern.
- **Scale**: one optional tag argument, `!ge(0.8)`, meaning doc ≥ 0.8 × operand. It is parsed when the pattern is built. A scale that isn't a number is an error in the pattern.
- **Composition** needs nothing new. `!at(a.b).ge 3` asks for an a.b that is ≥ 3. `!not.at(a.b).ge 3` also holds when a.b is missing. That is the reading `!at` documents for `!at(a.b).not 3`.

**It works for verse's case as written.** `trigger/match.go` evaluates `value` at the payload root, so for `quota.<org>.<dimension>` the root is `{limit, used, month}`, and `used: !ge(0.8).get-path(root) limit` names the sibling. It would not reach it in a match run from higher up, over `quota.*.*`: a relative path only goes down, and a root path would need the org. That's a separate gap (a `!get-path(parent)` anchor would close it), and this case doesn't need it.

## Numbers

- **Exact comparison, not float.** Compare with `big.Rat`: an int64 exactly, a float64 exactly (`SetFloat64`), and the scale from its decimal text (`0.8` is 4/5). So `used: 440` against `0.8 × 550` is exactly equal, and no case falls on the wrong side of a boundary through binary rounding. It also doesn't depend on 29xhvsd1: every number that parses today is int64 or float64, and a big.Int or big.Float later drops into the same comparison.
- **Mixed int and float compare by value** (`3 < 3.5`, `3 ≤ 3.0`). Note that this differs from equality: `trigger/match.go` pins numbers as type-exact (`{n: 2.0}` doesn't match `{n: 2}`), so `!ge 3` and `!le 3` together match `3.0` while `3` does not. I think that's right, since an order is about values, but the docs should say so.

## What doesn't match, and what is an error

| case | reading |
|---|---|
| the doc node isn't a number (string, null, object…) | no match |
| operand literal isn't a number | error, when the pattern is built |
| scale isn't a number | error, when the pattern is built |
| wildcard operand path | **error, when the pattern is built**, not a no-match as asked. `!get-path` already refuses a wild path there, and a pattern that can never match is better said once, where it is written, than as a silent false at every node. |
| operand path names nothing, or names a non-number | **the fork** — see below |

One consequence to document: `!not.ge 400` matches a string, and `!lt 400` does not.

## The fork: an operand path that names nothing

`!get-path` makes a missing path an **error**, and its doc explains why: the only alternatives are a null, which a match reads as "anything", or a silent no-match. The issue asks for a no-match here.

I recommend **no-match inside the comparison**. The reason `!get-path` gives is about answering with a value: there is nothing to answer, and a null would be wrong. A comparison consumes the value and answers a question, and "`used` ≥ 0.8 × a `limit` that isn't there" is a question a document can fail, which is the reading `!at` gives a missing path. `!get-path` itself would keep its error everywhere else. This is the tony-format owner's decision.

## Cost

It is small: one symbol file in `mergeop` with four names, their tests, registration in the match context, and the table in `docs/matchpatch.md` (a test keeps that table equal to `o match -tags`). On verse's side, `trigger/deselect.go` folds predicates three-valued with `tony.Match` as the leaf, so the new ops should be leaves there too.
