Correcting this issue: the diagnosis above blames Path() and "something in the
read/fold path". Both are wrong, and the first is exactly backwards.

The panic is an ASSERTION, and it is a correct one. A scalar cannot hold a
child, so a node whose Parent is a scalar is a tree that cannot exist. Making
Path() answer instead of panicking would delete the only thing that noticed, and
the malformed tree would travel on. The premise is right; the producer is what
needs fixing.

The producer is patch.go, and no store is involved:

    tony.Patch(ir.Null(), parse(`{a: !rename [{from: "x", to: "y"}]}`))
    panic: parent but not in container

    same with ir.FromInt(1) as the document;
    with `{}` as the document it is a clean error, "cannot rename fields in
    non-object at $.a of type Null"

    patch.go:397
      func absentAt(doc *ir.Node, field string, index int) *ir.Node {
          res := ir.Null()
          res.Parent, res.ParentField, res.ParentIndex = doc, field, index
          return res
      }

An object patch runs objPatchYWith whatever the document's type is -- doPatchWith
switches on the PATCH's type -- so a scalar document reaches the object merge,
where its empty Fields make it behave as an empty object and every field of the
patch goes through absentAt(doc, k, 0). The link that makes is a statement that
this null sits at field k of doc, and when doc is a scalar that statement cannot
be true of anything.

Where the store came in is only that it produced the shape: a scope whose
document had been deleted read back nil, verifyApplies folded that to ir.Null(),
and the next write's patch was an object. Nothing in the read path builds a bad
parent -- a walk over the scoped document at that commit finds none.

So the fix is in absentAt: the link is a claim about where the node would sit,
and it may only be made when doc can hold it. When doc is not a container, leave
Parent nil and let Path() answer "$" -- less specific, and true.

Worth deciding at the same time, because absentAt makes the same claim there
too: with an OBJECT document, absentAt(doc, "a", 0) points at doc with
ParentField "a" while doc has no field "a". Path() renders it ($.a, which is the
useful message) and the membership the panic is named for does not hold there
either. Either that is a legitimate "where this would go" device and the
assertion is only about the parent's KIND, or absentAt should not be forging
links at all and the path wanted for an error message should be passed down.
