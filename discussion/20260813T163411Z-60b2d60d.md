All four fixed on branch `issue-ps8kfs9d` (4 commits). Two corrections to the report, both about defect 1.

**Defect 1's stated cause is not the cause.** `logd/server/server.go` already fills in `DefaultConfig()` when `Spec.Config` is nil, and `o sys up` passes exactly that — true since before v0.0.126, so a store stood up the documented way did have a policy: `MaxCommits: 1000`. The early return at the top of `maybeCompact` only bites a server given a `-config` file with no `snapshot:` section.

What actually left `logB` at 0 bytes was three things, any one of them sufficient:

1. **The size threshold was a cliff, not a bound.** It was read against the whole active log, which never comes back down — a switch does not empty the log it switches *into*. Crossed once, never uncrossed: the store then snapshotted on *every* commit for the rest of its life. Measured, before the fix: 400 writes against a ~100 KB store, `maxBytes: 65536` → 153 snapshots and 4 MB of log. This is why defaulting `MaxBytes` without fixing it first would have shipped a worse outage than the one reported. It now thresholds the delta accumulated since the last snapshot, marked in dlog and persisted, so it survives a restart.
2. **Defaults were never applied to a config that was loaded.** A file configuring a schema and saying nothing about snapshots silently disabled snapshotting.
3. **The default policy was commits-only, and that count is per-process.** `commitsSinceSnapshot` is an in-memory counter reset at every start, so a pod restarting before its thousandth commit *of one life* never snapshots however long the store runs. That is what an empty logB after weeks actually supports.

`o sys up` now takes `-config` (the same file `o system logd serve` takes), and both servers log the snapshot policy on the way up.

Defects 2, 3 and 4 were confirmed exactly as written. Two notes:

- Removing the parse loop in `buildPatchValueIndex` exposed a second superlinear term underneath it — `maximalPaths` compared every pair of paths. Both are gone; one pass in segment order yields the maximal paths and each dominated root's dominator together. On a synthetic range in the shape of the store that wedged: 1000 entries 190 ms → 1.8 ms, 4.8M allocs → 20k. Cost is now linear in entries replayed rather than quadratic in the distinct paths they touch.
- For defect 4, bounding the handshake by `min(wireTimeout, ctx)` is not sufficient for a caller that cancels rather than expires — a blocking read notices neither. The connection is now closed under the read when the caller gives up. The session mutex guards state only; connecting and writing each got a semaphore a caller can wait on with its own deadline. Both regression tests fail on the previous code at exactly 30s.
