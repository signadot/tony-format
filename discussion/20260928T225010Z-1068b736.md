From the tony-format side: option (1) is implemented on branch `worktree-issue-gkmdvps7` (93796a9a, 1c36aa2c; not merged yet). The shape ended up as (A): the answer comes in the watch's own stream.

```tony
{id: p1, progress: w1}
{id: p1 result: {progress: {commit: 52795}}}
{event: {commit: 52795 path: verse.perms progress: true} id: w1}
```

In libctl it is `Watch.Progress(ctx)`, which answers C. The progress event arrives in `Events()` after every event for a commit at or below the one it carries: C, or a later commit the watch has already taken. For the perms mirror, that means the view is current through R once the applier has applied a progress event with `commit >= R`, whichever request prompted that event. A watch that ends first sends no progress event, and its ended event is the answer.

It works directly against logd and through docd for a base path. Through docd it is `unsupported` for a watch composed across mounts, and for a controller that doesn't serve it. Contract: docs/logd/session.md, "Is a watch current?".
