## Resolution — watch is fully supported by the library (controller-routed), not deferred

Corrects M1 recommendation #1 from comment #001. "Defer content-watch" was a library
deferral, which violates the reasonably-complete-library goal. The library must not
special-case or defer any operation.

Resolved:
- Full bidirectional MOUNT = MATCH + PATCH + WATCH. docd routes WATCH to the owning
  controller exactly like MATCH/PATCH; only non-mounted paths' watches hit logd
  directly. No operation is second-class.
- libctl controller runtime fully supports watch: HandleWatch is a first-class part
  of the Handler interface and DocdSession, alongside HandleMatch/HandlePatch. The
  library streams whatever events the controller produces.
- Declining is a per-controller choice, not a library gap. A controller returns a
  standard "unsupported operation" error for any op it doesn't implement, and docd
  relays it to the client. => MOUNT protocol needs a first-class `unsupported` error
  code (any controller can decline any op cleanly).
- The local:* connect-controller declines watch via that unsupported error. That is
  a property of that controller, not of docd/tony-format.

Also settled (per discussion, "agree on all"):
- #2 docd routes by path and stays ignorant of the index-vs-content distinction.
- #3 no read caching in M1; if added later, invalidate on the change stream, never TTL.
- #4 controller-served reads echo the `commit` they correspond to.

M1 scope impact: HandleWatch joins HandleMatch/HandlePatch in the M1 controller
runtime, and the `unsupported` error code is part of the M1 MOUNT protocol.
