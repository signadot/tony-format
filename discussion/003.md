## Implemented (splitter 316ed4d, coordinator + kpath fix 57dbc86)

A client patch spanning >=2 participants is split and committed as one transaction
transparently — the client just PATCHes; docd allocates a pooled tx id, routes
each mount's sub-patch to its controller and writes each base remainder over its
own logd link, then answers as one result. Precondition rides unsplit on one
participant. Higher-order ops (!all/!dive) above a mount boundary are rejected
(docd decomposes statically → less expressive than logd); which tags block is a
pluggable filter, default = "is a registered merge op". Per-participant timeout
threaded to all participants so a failure aborts rather than hangs. Base writes go
at deep paths (root would prefix-conflict in the tx merge). Single-participant
patches route as before.

Design correction found while building this: docd's path layer used "/"
separators, but paths are kpaths (.field/[i]/{i}) — logd treats a slash path as
ONE literal field. Now paths are kpaths with NO leading slash (mounts too; nested
= a.b). This also debunked an apparent "logd can't read below a write" limitation
— it was purely the slash bug.

Participant model as decided: mounts touched + (base data present ? 1 : 0); the +1
(docd's logd link) writes the base remainder.

Tests race-clean (split unit tests + e2e multi-mount incl. nested deep-kpath read,
mount+base, undecomposable rejection, CAS abort).

Known follow-ups (not blockers): scoped multi-mount tx (issue 3vm6gq21); faster/
explicit abort (currently timeout-based); base-participant connection pooling;
array/sparse segments in split paths (fields only today).
