The fix proposed in the report -- root a !delete where the loop continues, mirroring claimDelta -- does NOT work, and the reason is structural.

api.NextState(overlay, rooted) is Patch: the left operand is a DOCUMENT and the right is a PATCH. An operation already sitting in the overlay is data at rest and survives; an operation in the thing being unioned in is an instruction and executes against the overlay. Measured, all three cases:

  overlay so far {d: {k1: 20}}           + tombstone -> { d: { k1: 20 } }   evaporates
  overlay so far {d: {k0: !delete null}} + tombstone -> { d: {} }           destroys the tombstone
  overlay so far {}                      + tombstone -> { d: {} }           evaporates, leaves a spine

The last is the same empty container a scoped delete of an unwritten path already produces, so it is not even a new shape -- it simply does not record the claim.

The existing code is fine on the converse: a tombstone the DIFF half produced does survive a sibling being unioned on top of it --

  { d: { k0: !delete null k2: 1 } } + owned d.k1 -> { d: { k0: !delete null k1: 20 k2: 1 } }

-- because there the tombstone is in the left operand.

So a tombstone can only be in the overlay by being BUILT into it. That wants a patch-level union in place of a patch application. tx.MergePatches is the patch-level combiner in the tree and its kTree builds exactly this shape, but it cannot be used as-is: it merges by path and refuses a path that is a descendant of another, while the diff half is a whole-document patch rooted at "", which every owned path is a descendant of.

Two further things to settle before writing it, neither of them checked:

  ordering, since absent paths need the shallowest owned one -- a scope that
  deleted d and had earlier written d.k0 owns both, scopeOwnedLeafPaths keeps
  only d.k0, and a tombstone there would build d: {} where the scope holds no d
  at all;

  keyed elements, where absence means removing an element from a keyed list
  rather than deleting a field, and RootKeyedListAt takes values.
