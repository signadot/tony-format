Found and fixed in b2c030b. Your recipe was right; the layer is logd storage, and the cause is one line repeated eight times:

    return parentPath + "." + field.String

logd renders a child path by concatenating the field name after a dot, never quoting it. A name holding a dot becomes two segments, and every reader downstream then agrees with the rendering instead of with the document. It only shows from the first snapshot on because that rendering happens where patches are folded onto a BASE — before that a patch is applied document-shaped and no path string is built. Both of your masking traps follow from the same thing.

kpath.ChildField is now the one way to render 'the child named f', used at all eight sites (patch-root walk, graft, patch index, log-segment index, both scope-overlay walks, key tags, auto ids, schema walk, storage validation).

Two more where the string was read back as a path: splitFieldSegment scanned bytes for '.' and split a quoted segment apart; and the graft asked GetKPathWith for a field name handed over raw, found nothing for `post.dotted`, and dropped the write silently — that lookup's error is now returned rather than swallowed, since swallowing it is what made the loss quiet.

TestDottedFieldNameAcrossASnapshot covers ids with a dot, a slash, a space and a brace across two snapshots, with distinct ids after each one. It fails on the old rendering. I used SwitchDLog directly rather than 1000 filler writes — same code path, 0.08s.

One thing your side should know: index entries already persisted with the unquoted rendering stay ambiguous, so a dotted id written before this fix stays where it was put. Nothing rewrites them — the 192 standing refs will need a sweep, or to be deleted at the split address.
