The other half of this, for whoever implements around it: liveness is already free, and that is what makes the split clean.

logd answers a ping inline, with no storage in the path at all (session.go:229):

    case req.Ping != nil:
        s.send(api.NewPongResponse(req.ID))

So 'my connection to the substrate is alive' costs nothing today. What costs a document is 'where is the store', and a Pong carries no commit — which is the complaint above, and also the reason the two questions separate rather than one endpoint trying to be both:

  - liveness            Ping. Free, no read, no watch.
  - am I caught up      a number the process already has: the write's own commit comes
                        back in the patch result, and a watch event carries one. Kept
                        in memory and read out, it costs a probe nothing and is exactly
                        as current as the process's own knowledge, which is what
                        readiness means.
  - the census          rev, gates, runners, sources, tasks, strata. Fine to be
                        expensive, because a person asks for it rather than a kubelet
                        on a timer.

So a caller does not need a cheap revision query to make a readiness probe honest — it needs to stop asking the store. This issue still stands on its own for the callers that genuinely want the head and have nowhere cheap to get it (a tool reporting where a store is, a health check outside the writing process), and 'a commit on the Pong' remains the smallest of the four shapes above, since it would serve both questions in one request that already costs nothing.
