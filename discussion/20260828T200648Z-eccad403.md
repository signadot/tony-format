# sweep of logd-patch-root handling, plain vs lowered

Same write, both ways, compared at the index -- what paths each records and which of
them a read may skip.

```
a.b <- {k0: 9}
  PLAIN entry: a: b: !logd-patch-root { k0: 9 }
    ""      spine=true     "a"     spine=true
    "a.b"   spine=FALSE    "a.b.k0" spine=false
  LOW   entry: a: b: k0: !insert.logd-patch-root 9
    ""      spine=true     "a"     spine=true
    "a.b"   spine=TRUE     "a.b.k0" spine=false

a <- {c: {d: 3}}
  PLAIN entry: a: !logd-patch-root { c: { d: 3 } }
    "a" spine=FALSE   "a.c" spine=FALSE   "a.c.d" spine=false
  LOW   entry: a: c: d: !logd-patch-root 3
    "a" spine=TRUE    "a.c" spine=TRUE    "a.c.d" spine=false
```

## the mechanism, which explains the selectivity half exactly

`passesThrough` answers false for ANY tag, the marker included:

	n = ir.Uncomment(n)
	if n.Tag != "" { return false }

So WHERE the marker sits decides which segments are skippable. The plain path marks at
the client's write path, so everything from there down is non-spine -- conservative,
always read. The lowered path marks deeper, so the nodes between are spine.

That is the whole of why root marking breaks `TestNarrowReadIgnoresSiblingWrites`: a
marker at the root makes the root segment non-spine, `lookupSubtree` cannot skip it,
and every narrow read collects every commit. Which is `ap8ddvp2h12krd43gdn0` again,
reached from the other direction.

## and it does NOT explain the eight

`lookupSubtree` skips a spine segment only for a NON-ROOT read:

	ancestor := kp != ""
	if ancestor && c.Spine { return true }

`CheckHead` compares against `replayBaselineAt(commit)`, which reads at "". A root read
takes every segment, spine or not. So the spine difference cannot be what drops those
eight heads, and this sweep rules itself out for them.

## two things worth following up

**Comments move the flags.** With a comment on the write, LOW's entry is
`a: b: !comment.logd-patch-root {head: [...], value: {k0: !insert 9}}` and `a.b` goes
back to spine=false, because the !comment tag is there. So the comment op changes which
segments a narrow read may skip -- not wrong on the face of it, since a node carrying
an operation is exactly what should not be skipped, but it means the delta's comment
handling and the read's selectivity are coupled.

**PLAIN's `a.c` is spine=false and looks like it should be true.** It is a plain
container with fields and no tag -- `{d: 3}` under `a.c` -- which is `passesThrough`'s
own definition of a spine. Both the marked node `a` and everything beneath it come back
non-spine on the plain path. Either something propagates non-spine downward or the node
carries a tag that is not visible in the rendering. Worth knowing before trusting the
flag, and it is the plain path, so it predates lowering.
