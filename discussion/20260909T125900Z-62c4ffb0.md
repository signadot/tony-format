The property this issue asked for -- cost per scoped write proportional to the scope's
OWN footprint, whatever baseline does in between -- is what the footprint gives: the index
keeps, per scope, the statements no later statement dominates (110236e), and a scoped read
folds those and not the scope's history (9f13add). A scoped write's verification reads and
its preconditions go through the same read. Measured with this package's TestScaling_Writes
and the interleave test this issue attached, cost of the Nth after N of the same, N=50..400:

    scoped write, unconditional   was 2.26ms 4.13ms 7.88ms 17.8ms    now 444us 471us 447us 498us
    scoped write, CAS             was 6.5ms  6.45ms ...             now 505us 528us 514us 549us
    the interleaved pair          was 3.87ms 4.86ms 8.35ms 15.2ms    now 2.33ms 1.41ms 1.39ms 1.42ms
    (baseline write alone ~690us, so the scoped share of the pair is ~700us)

Flat, and a scoped write is cheaper than a baseline one, since a scope stores its claim as
sent and baseline diffs. The interleaved row is TestScaling_ScopedWriteInterleaved now, so
it stays measured. Nothing is kept, stepped or materialized: a scope's snapshot of a path
is its last covering statement there, and the index knows where that is.
