## M2 progress + a design question surfaced

Landed:
- edf6c3b: `o sys up` fixed for the two-listener model — starts docd client
  (-docd-addr :9124) AND mount (-docd-mount-addr :9125) listeners, connects
  txpool, clean SIGINT/SIGTERM shutdown. Verified by running the binary. up is
  foreground (Ctrl+C = down); no separate daemon-managing `down` yet.
- c96fe19: failure-injection test — an in-flight client op fails deterministically
  (not a hang) when the owning controller crashes mid-op (exercises failAllRoutes).

Design question surfaced (needs a decision before it's "reasonably stable"):
when a controller crashes, its mount unregisters, so subsequent ops to that path
fall through to logd and return null/empty rather than an error. For the
connect-controller (content not in logd), that is silently wrong — a read of a
crashed content controller's path should error, not return empty. Options:
(a) keep fall-through (simple, but silently wrong for content mounts);
(b) tombstone a crashed mount so its subtree errors until remounted;
(c) make it a per-mount policy.
Leaning (b)/(c). Flagging rather than silently choosing.

Still open for M2/M3: docd<->logd reconnect; wiring txpool for multi-mount
transactions; the crashed-mount policy above.
