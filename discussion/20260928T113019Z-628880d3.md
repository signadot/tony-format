Feedback-loop review, 2026-09-28. Checked by running a watch against each setup, not by reasoning alone.

- **One repository**, with a pulling watch fetching every 30ms over an unpushed change, a contested issue and a moved mirror: ten pulls with nothing printed and no ref moved. After a push, one `pushed to origin` line per issue, then quiet.
- **The set, run outside a repository**: two repositories, each with its own origin, each mirroring an issue of the other through the other's origin. The steady state was quiet with no ref moving. One comment pushed in b printed three lines, each once: b `(local)`, b `pushed to origin`, and a's mirror `(local)` once a's refresh took it. A push from a printed one line in a and nothing in b.

No loop: a pull only reads tracking refs, `trackPushed` runs only on a push that lands, and a second push sends nothing. What remains is that an agent hears its own push. 185abc22 says so in the tool descriptions and docs.
