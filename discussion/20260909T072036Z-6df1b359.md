-m Delivered by the logd rebuild (wk5w1ddkh12krj1tkxn0), phase 7 (9a54d21), and not by the mechanism this issue proposed. No overlay and nothing materialized: since a stored scope write is ABSOLUTE after phase 3b, a scope's entry beyond the cutoff can simply GO when a later entry of the same scope dominates it -- states every path it stated, or an ancestor, in a way that does not depend on what was there. The fold of what remains is the fold of everything.

The cover rules were written from the fold's own behaviour rather than the operations' names (scope_compaction.go): !raw and !delete cover everything at and beneath their path; a plain scalar or an array of plain scalars replaces its path and everything beneath, but at its own path may keep a comment or a tag, so it dominates only an untagged uncommented statement there; an array with object elements, an empty object, and every other operation cover nothing. One walk of the scope newest-first, one read per entry per compaction.

Held against a store that never compacts, both views, every path, 150 seeds; and verified non-destructive on a real staging store -- 3,261 of 3,288 patches removed with the readable document byte-identical, 216,198 bytes, zero differing lines.

RESIDUE, deliberately not built: a per-scope replay floor. A dropped scope entry raises the store-wide floor, so a baseline watcher resuming from before it re-initializes too -- pessimistic, and only for a resume from beyond the cutoff.

Note this bounds what a scope's log HOLDS, not what a scoped read PAYS: a scoped read still replays the scope's own patches at the path from commit 0, because path snapshots are baseline's. That cost is 9b2vpggxh12ks0qde5n0 and sb33w8p9h12kr16kg5n0, both still open.
