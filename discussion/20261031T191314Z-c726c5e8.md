**Correction.** The first fix, 5988e0a9, refused the bare tag on the wire with "a tag must be followed by a value". It read that from docs/tony.md's Key Sets sentence. That was wrong. In brackets a tag with no value is a tagged null, decided in 0c466dff (pkj422gkh12kr24gj1n0), which came after that sentence. The parser and token.balanceOne read it that way, and so do the Tags section examples. 5988e0a9 also refused `{a !delete}`, one of those examples.

The fix that replaces it takes the issue's first option. A `}`, `]` or `,` after a tag ends the value there, and the decoder emits a tagged null, as the balancer does. The issue's request now decodes as `note: !delete null`, and the request behind it is read. The sentence that misled the first fix is recorded in v5dn9vfbh12krj9xwsn0.
