Not a stall: the decoder gave the bare tag to the `}` that followed, the state refused that as "key or int key, no val", and the session's reader returned the error, so the session ended and nothing after the request was read. From the client that is an unanswered request and a dropped connection.

Fixed by taking the spec's side, docs/tony.md (Key Sets): a tag is not a value, so the decoder refuses a tag before `}`, `]`, `,` or a key with "a tag must be followed by a value: !delete is followed by "}" ...; write `!delete null` for a null", the tokenizer's wording for the indented form. The session still ends on a decode error, as it does for any malformed wire document, but the log now says what was wrong and what to write.

The bracketed parser accepts `{a: !delete}` as `!delete null`, against the same spec sentence, which is why parse.Parse read the storage tests' patches: v5dn9vfbh12krj9xwsn0.
