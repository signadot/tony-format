Fixed in afacf92. The schema type mapper now consults `encoding.TextMarshaler` before every other branch in `GoTypeToSchemaNode`, so the signature says what the generated code emits.

The defect showed up two ways, not one. Same-package named scalar → `.[int]` for a value that is always a string (the `entity.Entity` `ref` case). Cross-package type → a reference to a schema that does not exist: `created: !time:time null`, `format: .[nullable(format:format)]`. Both now map to `.[string]` / `.[nullable(string)]`, and the dangling `time:` / `format:` context imports go with them.

Five committed schemas in this repo were wrong and are regenerated — including `stream`'s own wire event type, which said `t: .[int]` for a field the generated code writes with `MarshalText`.

Scoped to the field's own type. A `[]T` of a TextMarshaler `T` is deliberately untouched: neither encoder marshals the elements as text (codegen emits `ir.FromInt`, and so does the reflection path), so `.[array(int)]` there is already the truth. `gomap/codegen/testdata/textscalar` carries all four shapes and `TestTextMarshalerSchemaMatchesCodegen` asserts the schema and *both* encoders agree field by field, rather than pinning the schema text alone.

One instance of the same symptom is left behind, by a different cause: `system/logd/storage/tx` still publishes `Timeout: !time:duration null` while the generated code emits `ir.FromInt` — `time.Duration` has no `MarshalText`, so this is the cross-package-named-type branch emitting `!pkg:typename` without checking that such a schema exists. That is item 8/14 territory and needs its own decision (fall back to the underlying kind when the referenced package has no schema for the type?), so I left it rather than widen this fix.
