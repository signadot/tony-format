## step 1 done: b39eca8

`storableDelta` is the one place. `unconditionalPatch` is gone. The four silent
differences between the two columns are now three explicit caller decisions
(presentation, comments, marking) with the reason for each written where it is made,
and one that was never a difference (validation).

Two things it turned up, both worth having before step 2.

**The vocabulary is no longer what guards a keyed array.** A positional fall-through in
`diffArray` used to become an `!arraydiff`, which is not storable, so it was refused. An
absolute delta has no `!arraydiff` to refuse -- it states the array WHOLE. For baseline
that is correct. For a scope it takes ownership of every element, so baseline can never
add one again, and the only thing standing in the way is now `scopeHasKeyedPaths` and
`lowerWrite`'s own undeclared-key check.

Absoluteness and identity-preservation are different properties. Making every delta
storable does not make every delta keep what a keyed array is for. That raises the
priority of step 3 -- the keyed fact -- from "the last simplification" to "the only
thing guarding a scope's arrays".

**Lowering EVERY scoped write diverges.** Under the shipping rule the scoped
differential is clean at 25 seeds. Under `LOGD_LOWERING=all` it is not. That mode is not
what ships, and the difference is the question step 2 has to answer before the gate
comes out: a scoped write lowered against the SCOPED view produces a delta describing
baseline+scope, and what the scope should own is only the part the write touched. It
happens to be only that today, because next = base + patch. Whether that survives every
shape is exactly what the gate removal needs to establish, and it is now measurable.
