# the snapshot-boundary class, first pass

With the value divergences gone (201aeca), this is what is left: 24 cases of "the
snapshot check dropped the head", and it is now known NOT to be downstream of the
first class -- it survives their removal and ticked up slightly, 20 -> 24.

## what it is

`SwitchDLog` calls `CheckHead`, which compares the stepped head against
`replayBaselineAt(commit)` and drops the head when they disagree. The head is verified
correct against the reference at every commit by the assertion just above, so it is the
READ that is wrong -- and the read is the one path that differs between the two stores:
the subject snapshots, the reference never does.

So: replaying a lowered log THROUGH A SNAPSHOT gives a different answer from stepping.

The disagreement is missing and stale values rather than structural damage:

```
head: a: b: c: k1: 19 k2: 21 ... d: e: ... k0: 22 k1: 16 k2: nested: 23
read: a: b: c:        k2: 21 ... d: e: ... k0: 13        k2: nested: 15
```

`a.b.c.k1` is absent from the read, `d.k0` reads 13 where the head has 22, `d.k1` is
absent. Every difference is the read holding an EARLIER value or none, so the read is
not applying some entries rather than applying them wrongly.

## what has been eliminated

**Marker depth is implicated and is not the mechanism.** Marking the delta's root
instead of where the change lands takes it from 24 to 14, with value divergences still
0 -- so the deeper marker costs something. But marking only as deep as the BASE
actually goes, on the theory that a marker at a path the base lacks has no events to
apply to, changes nothing at all: still 24. The base at commit-1 does contain those
paths. Reverted; it added a parameter for no measured gain.

That leaves marker depth as a symptom of something else rather than a cause, and root
marking is not a fix worth taking: it is what made every narrow read replay every write
(a read of verse.meta.rev went 125us -> 17ms after a thousand writes elsewhere).

## where to look next

The read path applies stored entries through the STREAMING PROCESSOR, and the head
steps through tony.Patch. head.go names that as the invariant this guard exists to
protect: "the read path applies the stored, still-tagged entries through the streaming
processor, while the head steps the stripped copy through tony.Patch. They are meant to
agree." A lowered delta is a shape the processor has not had to apply before -- the
client's patch names a path and asserts a value, a lowered delta names the shallowest
CHANGED node. Same paths, different shapes.

The next probe is a small deterministic one: write, snapshot, write, and compare
`replayBaselineAt` against the head with a delta of each shape, rather than another run
over generated seeds.
