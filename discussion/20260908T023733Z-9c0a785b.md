TWO FINDINGS worth more than the phase.

1. The patch-root marker made the ROOT NON-SPINE ON EVERY COMMIT. passesThrough reads any non-presentation label as an operator, TagPatchRoots puts !logd-patch-root on every merged patch's root, so the root looked like a write on every commit -- and a read at any path collected every entry in the store through the root's copy of it. The index now looks through logd's own marker. This is the read-side cost of the marker, measured, ahead of phase 4 deleting it; it also means the Spine flag's selectivity was never actually reaching a read below the root.

2. The design's "composed into one running delta" HAS NO PRIMITIVE. The format library has no patch-over-patch composition, and the processor itself, given several patches at one path, folds them one at a time onto the collected subtree. Read therefore holds the writes to kp since the snapshot as a list, each cut down to kp -- the "what changed under kp" term the bound admits -- and hands the processor that list. read_write_interface.md's step 2 is within its bound as built; a literal composition is a refinement and rebuild_plan.md now says so.

Also: an operator above the path no longer declines the read. Read is taken at the ancestor the operator is on and navigated down -- the operand that write installed is the admitted intermediate -- and the counters say the read was wider than its path. And absence is classified from the first event of the nearest present ancestor, no wide read behind it; the one case where the old spine was more generous than the document now agrees with it.

The server reads under a configured budget (storage.readBudget, default 64 MiB): decision 3's first half. Decision 2 was taken as recommended -- a goroutine per open cursor feeding a 64-event channel, Close cancelling it.
