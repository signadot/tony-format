Three things about how `!logd-compact` lands in verse, read against the code:

**1. `define:` is a path tree, not a set of types.** `walkDefine` (api/schema_parse.go) builds each declaration's path from the literal keys above it, and `Schema.Identity` (api/schema.go) matches a kpath by equality. So `define: iod: out: !logd-compact(0) …` declares the top-level path `iod.out`, not every iod's `out`. Verse's record sits at `verse.verse.iods.<name>.out`: the store root, verse's own root, `iods`, then the iod's name, which is whatever was installed. Today verse could only spell each iod by name, which ties the schema to the installed set: every `verse iod add` would want a schema commit. What would make the declaration static is a wildcard segment in `define:` (`iods: *: out: …`, or however logd would spell "every child of this map"), which keying has not needed so far.

**2. A pass does not write the whole record.** versed's `passIO` merges four fields into `out`: `delivered`, `failed`, `lastPass`, and `lastError` (a `!delete` on success, an object on failure). `out.places`, `out.as` and `out.requesters` come from the registration, in the same entry as `name`, `url` and `owns`. So "Verse writes the whole record each pass, so … every pass dominates the last" holds only per leaf. The rule as you wrote it still fits: a partial overwrite dominates what it restates, and the registration's entry also states undeclared paths, so it is kept whole. Declaring at `out` is therefore safe, and so is declaring the four leaves.

**3. A schedule's tick must not be declared.** The `tick: !logd-compact(1h)` example is exactly the past-commit read the earlier comment ruled out. A tick causes firings, and a firing reads at its causing commit; staging's log this morning has rules doing exactly that (`read verse.verse.schedule."repo-charters.hackspace:minute".tick at rev 260099`), and after a gate that read can come hours later. Ticks stay at the store's cutoff. The paths verse would declare are `verse.verse.iods.*.out` at `0`, and probably `verse.verse.iods.*.lastReflect`; not the registration's own `lastError`, which is what a health rule would fire on.
