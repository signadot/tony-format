A read beyond the cutoff that finds nothing at the path answers `not_found` (logd/server/session_read.go:203 at 54cb22f4), and `api.Error` is a code and a message with no commit. So a path absent at the answered `S` comes back the same as a path absent at the `C` asked for. verse's `matchAt` reads `not_found` as a real "nothing there" (a never-written slice selects nothing), so the fallback passes silently for exactly the reads that find nothing. That is the silence this issue removes for a body, and the decision comment names existence among what answers from `S`.

What closes it: the not-found answer carries the commit it was settled at, for a read with a commit. Either the error says it, or an absent node is answered as a match result with that commit. Which shape is upstream's choice; verse needs only to be able to tell `S` from `C` on that answer too.
