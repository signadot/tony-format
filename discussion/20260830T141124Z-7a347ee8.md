WITHDRAWN — this is not a defect and the report misread merge semantics.

Deleting the only field inside a container IS writing `{}` there. It is library-level merge, not something logd adds:

    {a: {b: 1}}        + {a: {b: !delete null}}  ->  { a: {} }
    {a: {b: 1, c: 2}}  + {a: {b: !delete null}}  ->  { a: { c: 2 } }
    {a: {b: 1}}        + {a: !delete null}       ->  {}

The patch document names `a` as an object and the result of applying it is `a: {}`. So the writer wrote a patch whose result at `a` is an empty object, and a later read answering `{}` is answering with what was written. The rule from bymhrqz7h12ksas3jhn0 — a read answers X iff X was written — holds; I was reading "nobody wrote {}" off the shape of the patch rather than off its result.

The third line is the answer to the case I thought was missing: a writer who wants the container gone deletes the CONTAINER, not its last member. Both are expressible and they mean different things, which is right.

Nothing to fix. Closing.
