# class A, root cause

Reproduced minimally. It needs a node whose COMMENTS changed and whose VALUE changed,
in the same commit:

```
a:  # new          b:  # new
    d:                 d:
      e:                 k0: 9
        k1: 5
      k0: 9

DiffAbsolute answers   !insert d: k0: 9
applying it gives      d: e: k1: 5  k0: 9      <- e survives
```

Every other arrangement of the same delete is correct -- no comment, a comment inside
`d`, a comment on the node being deleted -- and answers `d: e: !delete k1: 5`.

## why

`diff()` opens with

	if d.cfg.Comments && !sameComments(from, to) {
		if cd := d.commentDiff(from, to); cd != nil { return cd }
		return d.makeDiff(from, to)
	}

`commentDiff` declines when the value moved as well ("something else moved; MakeDiff
states it whole, comments included"), so a node whose comment AND value both changed is
answered WHOLE. That is right for the ordinary diff -- `!replace{from,to}` carries both
sides and installs the new one entire.

Absolute has no `!replace`. It answers with `!insert <value>`, and the value here is a
CommentType WRAPPER, not an object -- so:

- the object branch in `makeDiff` does not fire, because it tests `to.Type`, and the
  wrapper is not an object. The whole document is answered instead of the field.
- the `!insert` lands on the wrapper, where the op dispatch does not look, so it is
  INERT. It merges rather than replacing, and the deletion is lost.

So the delta says "d is {k0: 9}" in a form that means "merge {k0: 9} into d".

## the fix is not "look through the wrapper"

Tried: uncommenting `to` as well, so the object branch fires and the fields are stated.
That fixes the deletion and makes everything worse -- 5 value divergences to 21, plus
`TestCommentedPayloadIsReadable` failing, because descending past the wrapper drops the
comment, and the comment is what sent this node to `makeDiff` in the first place.
Reverted.

The answer has to do BOTH: descend for the fields, and state the comment separately.
`!comment` is in the storage vocabulary and is absolute, so the delta can carry both --
the diff just has no path today that produces them together, because the ordinary
answer bundles them into one `!replace`.

## and this settles the !insert question

`!insert` as a whole-container REPLACEMENT is the wrong primitive to lean on:

- it is inert on a comment wrapper, silently, as above;
- an index would have to learn that an `!insert` at a path invalidates everything
  beneath it, which nothing in `IndexPatch` does today -- it walks the delta and
  records the paths it finds, and the paths that WENT AWAY are recorded from the
  payload under a `!delete` (which is why emptying that payload broke
  `TestAbsentPathAnswersAsTheDocumentWould/verse.gone.zz`).

Both go away if an absolute diff never replaces a container: state the fields that
changed and `!delete` the ones that went. `!insert` then means only what it has always
meant in a stored delta -- "this field was not here" -- where merge and replace
coincide and the index already handles it.

So: do not teach the index about a bare `!insert`. Remove the need for one.
