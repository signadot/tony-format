item 11: reproduced on main at 6ddd0281 (a NoInit watch on a quiet watchable controller path: client.Watch with a 1.5s context times out; libctl/controller.go handleWatch confirms only on the handler's first emit or on its return). NOT fixed: the fix is a contract decision, not a local change. The runtime cannot tell a handler that has accepted a NoInit watch and is waiting for a change from one still deciding, because Handler.Watch's only acceptance signal is emit, and a NoInit watch on a quiet path has nothing to emit; the lazy confirmation exists so a handler can decline with ErrUnsupported before the confirmation, which docs/logd/session.md requires of a refusal. Two shapes, either of which is Scott's call: (a) an explicit acceptance in the Handler contract -- emit(nil), or a WatchParams.Accept func -- which a handler serving a NoInit watch calls once it has accepted; handlers that never call it keep today's behaviour, so every controller must adopt it; (b) the runtime confirms a NoInit watch up front and a later ErrUnsupported becomes a terminal Ended event with reason unsupported, which the client sees on Events() rather than as Watch()'s error, so unsupported would join invalid_path as a non-re-establishable ending in WatchEndedError's contract. Composed sub-watches are unaffected (they do not wait for the confirmation), and a logd-served path confirms as before.
