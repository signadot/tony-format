Intent for a read that finds nothing, answering the two points above. Both are on branch `issue-cpqj2tf6`; neither is merged yet.

## 1. libctl hands the commit back

`LogdSession.MatchAtCommit(ctx, path, commit)` returns the node and the commit it was answered at (54cb22f4). `MatchAt` is unchanged and still drops it.

## 2. A not-found says which commit it found nothing at

Shape chosen: **the error carries it** (d0674ae3). `SessionError` gains an optional `commit`:

```tony
{id: "7", error: {code: not_found, message: "...", commit: 80}}
```

An absent node stays an error, not a match result with no body, so a client that already handles `not_found` keeps working.

**When it is set.** Only on a read that named a `commit` (or a set page continued by a cursor, which reads at the cursor's commit). It is set on the three errors that answer what the state holds: `not_found`, `path_conflict`, and `invalid_path`. It is always the commit the read was settled at: the commit asked when the read is exact, the earlier snapshot's commit when it isn't. A read with no `commit` carries none, and neither does an error that isn't about the state (`commit_not_found`, `storage`, ...).

**What a client does.** Compare the error's `commit` to the commit asked, the same test as on a body:

```go
_, at, err := sess.MatchAtCommit(ctx, path, c)
var se *api.SessionError
if errors.As(err, &se) && se.Code == api.ErrCodeNotFound && se.Commit != nil {
    at = *se.Commit // nothing there, at this commit
}
// at != c: answered from an earlier commit
```

libctl needs nothing new for this: its errors already wrap the `SessionError`.

**A set with no members** was never an error. It answers `done` with its `commit`, which is the answered commit since 54cb22f4.

**Through docd.**
- A read routed whole to logd passes through, error and commit included.
- A composed read: when logd's own part finds nothing at an earlier commit, docd reads every source again at that commit, as it does for a body. If every source is absent, the composed `not_found` carries the commit.
- A logd that doesn't send the field (older than this change) is read as "answered at the commit asked", which is what it did.

## Not covered

- **A read routed whole to a mount.** A mount's answer carries no commit at all today, on a body or an error, so such a read reports `commit: 0`. Filed as ew3dnqpkh12krrk7qxn0. If verse's `AsOf` paths sit under a mount, "answered commit differs" would fire on every read until that is closed.
- **Scoped reads** (em3dnqpkh12ks0jzqxn0), as before.

A watch from a commit whose state is no longer exact is a separate fix on the same branch (er3dnqpkh12krsb2qxn0): refused with `replay_compacted`, not answered early.
