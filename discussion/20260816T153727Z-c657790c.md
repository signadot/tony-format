Closing: both halves are answered, and what is left is a different statement, filed as
3xn08cb6h12kr4psg5n0.

The execution half, ee1b9d4: mergeop had said which operations call out to the system since
before logd stored anything -- Unsafe(), and a RejectUnsafe option -- and nothing set it.
api.NextState sets it now, which covers every one of the eleven places logd applies a patch, and
a write holding such an operation is refused in NewPatcher so a store never has to fail reads to
enforce it. mergeop.FindUnsafe stops at !raw, so an escaped document that CONTAINS a patch is
still storable.

The poisoning half, 8e1b334: not the vocabulary in the end. A well-formed arraydiff or replace
stores and reads fine forever; a malformed one made every read fail. The cause was that logd
stored deltas it had never tried to apply, so the fix is to apply them first, and it covers
every way a delta can fail to apply rather than the operations that happen to be able to.

The recommendation in this issue was therefore wrong where it argued for holding a BASELINE
write to the vocabulary: that refuses correct writes to catch incorrect ones, and baseline gets
away with relative ops for the reason the charter itself gives -- its replay is deterministic.

What survives is the case where that reason does not hold. A SCOPE's base moves, so an operation
a scope stores can stop applying long after it was verified, and the scope becomes unreadable
with nothing wrong at the time of the write. That is what the vocabulary is for and it is
enforced on the overlay logd builds and never on the write a client sends:
3xn08cb6h12kr4psg5n0.
