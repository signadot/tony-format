Done in 19a6a81, the way you called it: the contract is in TagCompose's doc, it panics on violation, and checking is the caller's part.

One correction to my own report — the rule is narrower than 'no parens or commas'. An argument MAY hold parentheses, because an argument may be a tag: !retag composes over `bracket.key(meta.name)` and !map takes `array(int)`. So TagArgOK is: non-empty, parentheses balanced, no comma outside them. My first version refused the three characters outright and the diff/patch property test caught it immediately, which is the test doing its job.

Caller side: logd is the one taking such a name from data (scope_overlay and key-tag injection write !key naming the schema's key field), so api.Schema.Validate now refuses a key field whose name no tag can hold — the error names the path and the field, where a person can fix the schema, rather than panicking three layers down.
