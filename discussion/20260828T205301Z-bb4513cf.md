## the union has to walk THROUGH operands, not check the endpoint

First attempt was to ask `mergeop.OperandPaths` about the overlay node at the owned
path, and merge into the operand's value when there is one. It does not fire, because
the owned paths are LEAVES and the operator is at an ancestor:

```
own path="d.e.k1"  at=false  operand=false     <- GetKPath cannot reach it
own path="d.k1"    at=true   operand=true
```

`d.e` is the `!comment`, and `d.e.k1` does not exist under it -- the operand has `head:`
and `value:`, and `k1` is inside `value:`. So `RootPatchAt("d.e.k1", val)` builds a
spine the overlay does not have, and `api.NextState` merges it in beside the operand's
own fields.

So the fix is a walk that steps THROUGH an operand as it descends: at each segment, if
the node carries an operation, continue inside the part `OperandPaths` says is the
document value, and resume the remaining path there. That is the same walk the index
got in 81deb91, applied to a path rather than to a whole tree.

Reverted the partial attempt rather than leave a check that cannot fire.
`TestLoweringScopeDifferential` is committed and skipped against this issue, so the
reproduction is one `t.Skip` removal away.
