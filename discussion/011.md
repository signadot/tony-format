## Crashed-mount policy decided + implemented: tombstone -> error (f5bdf09)

Resolves the design question from #010. Chosen: a crashed controller's mount is
tombstoned; ops on its subtree return controller_unavailable until a controller
remounts the path — the correct behavior for content mounts (content lived in the
controller, not logd, so falling through to logd was silently wrong).

Implementation: MountEntry.Live() (live iff non-nil Session); disconnect
tombstones by session (can't clobber a remount); Register replaces a tombstone
on remount but rejects a live mount; client routing classifies live->controller,
tombstone->controller_unavailable, none->logd. Tombstone replaces the entry with
an immutable copy so LookupPrefix's lock-free readers stay race-free. Tests cover
post-crash error and remount-restores-service; race-clean.

Remaining open for M2/M3: docd<->logd reconnect; wiring txpool for multi-mount
transactions. (o sys up and controller-crash handling now done.)
