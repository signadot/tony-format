Comment 007's items fixed (on main, unreleased), plus a related edge case I filed as item 15.

- **Item 12** (`omitzero` on a value-struct field ignored) — the scalar and collection cases carried omitzero, but the value-struct branch emitted its nested ToTonyIR call unconditionally, so `Config{Addr:"x"}` produced `format: {}` / `llm: {}`. Guarded now with the same `isZeroValue` check optional fields use (helper generated, `reflect` imported, field wrapped in `if !isZeroValue_T_F(s.F)`). Both paths drop a zero struct and keep a non-zero one. `commit` codegen: honor omitzero on a value-struct field

- **Item 13** (blank-field marker silently ignored) — a schema tag on a named field (`_ struct{}`) is not a form codegen reads, so the package processed, exited 0, and generated nothing. It now errors, naming the field and pointing at the forms codegen does read (a `//tony:schemagen=` doc comment or an anonymous embedded marker). `commit` codegen: diagnose the blank-field schema marker

- **Item 14** (cross-package alias unresolved) — since Go 1.23 an alias's `Type()` is a `*types.Alias`, not the `*types.Named` it targets, so `FindNamedType`/`FindStructType` failed with "is not a named type". Resolved through the alias with `types.Unalias`. A `*pkg.Alias` field now resolves and round-trips. `commit` codegen: follow type aliases across package boundaries

- **Item 1, decode direction** (the asymmetry you spotted) — `fromIRReflectWithVisited` checked for a `FromTonyIR` method only in its pointer branch, so a value field (map or struct) with a custom codec was walked structurally on decode while a pointer field dispatched — the exact bug item 1 removed from encode, still present in decode. Added the symmetric non-pointer dispatch via `val.Addr()`. Reflection now dispatches both directions for value fields, matching generated code. `commit` gomap: dispatch FromTonyIR for non-pointer values (decode)

- **Item 15** (new — found while testing item 14): a package whose schema types are **all** `codec=custom` generated a `_gen.go` with the fixed header imports but no method bodies — every import unused, so the package would not compile. codegen now emits a package-only file (no imports) when nothing is generated. `commit` codegen: emit a package-only file when nothing is generated

Every fix has a cross-path / round-trip regression test; all codegen packages regenerate cleanly, and `api_gen` / `o b` are unaffected throughout. Leaving the issue open in case the re-evaluation turns up more.
