## Correction to #008: multi-client same-path watch is fixed, not deferred

#008 flagged "two clients watching the same mounted path collide" as an M2
follow-up. That was wrong to defer — silent breakage of a concurrent watch is a
correctness defect, not a robustness nicety, and does not meet the reasonably-
complete bar. Fixed in commit 6ce36d5.

Fix: the controller runtime now keys watches by the docd-assigned watch id (not by
path), so each client's watch is independent. UnwatchRequest gained an optional
WatchID (additive; logd ignores it) so docd cancels exactly the intended watch.
Also fixed a data race it surfaced: ir encoding mutates node linkage, so the
runtime now copies events before defaulting path and encodes under the write lock
(docd fan-in points do the same). New test: two clients watch the same mounted
path; both receive broadcasts; one unwatching leaves the other streaming;
race-clean.

Remaining real M2 items (not correctness gaps): txpool not wired for multi-mount
transactions; docd->logd reconnect / "outcome unknown"; o sys up|down.
