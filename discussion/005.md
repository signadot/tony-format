## Correction to D3 (comment #004) — match/patch expressivity + format negotiation

D3 was wrong on two counts.

### Match/patch expressivity is already in the logd protocol (not tied to wire format)
- MatchRequest.Body is PathData{Path, Data *ir.Node}; Data is a match pattern.
  server/match_data.go filterState runs tony.Match(item, Data) + tony.Trim(Data, item)
  — i.e. field selection (null = include) and !trim filtering.
- tx.Patch carries Match *PathData as a precondition (path + match + patch).
- So the !apiop {path, match, patch} triple maps DIRECTLY onto logd's existing
  Match/Patch. Those !apiops were the surface for this machinery.
- Newline-delimited Tony is just wire framing, orthogonal to op expressivity. What I
  called "logd's simpler ops" was only the convenience wrapper LogdSession.Match(ctx,
  path) omitting the Data pattern; the wire protocol carries the full pattern.

Corrected: docd's client face inherits FULL match/patch expressivity for free — no
"simpler ops" ceiling in M1. Only genuinely deferred: docd-level cross-controller MATCH
composition (one query fanned across mounts and recombined), a docd orchestration
feature, not a limit of the match model. libctl should also grow a Match variant taking
a Data pattern to expose this (additive; leaves LogdSession API stable).

### Format negotiation is a recorded intent (add as a component)
Closed issue hvn7ptxch12krra18xmg documents EncodingOptions (wire, brackets) in the API
layer, carried per-request (!watch {meta, body}). Intent: client chooses encoding
(wire / json / yaml). Today everything hard-codes gomap.EncodeWire(true) — logd
responses, libctl requests, docd mount — so honoring a requested format is not wired
even in logd yet (known gap, consistent with the intent).

Additive + reinforces switchability: the hello handshake carries an encoding option
(logd Hello already has ClientID/Scope; a Format field slots in additively), and docd
must pass it through rather than re-hardcode wire. New plan component:

L. Format/encoding negotiation — client requests wire/json/yaml via the hello
   handshake (EncodingOptions already defined); logd honors it (currently hard-coded to
   wire); docd passes it through end-to-end and to controllers. Additive on the
   protocol; do not hard-code EncodeWire.
