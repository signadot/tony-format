Items 10 and 11 fixed in go-tony v0.0.89.

- **Item 11** (`omit` / `-` / `field=-` ignored on the reflection path) — the reflection encoder and decoder now honor all three omission spellings via a shared `tagOmits`, so a field marked not-to-serialize (a secret) no longer leaks, and the same tags produce the same document on both paths. codegen's parser also recognized `omit` and `field=-` but missed the bare `-`; aligned. This corrected a latent leak in go-tony's own `issuelib`: `Issue.Ref`/`.Title` (`tony:"-"` derived fields) were being written to the wire under their Go names.

- **Item 10 Part A** (`omitzero` a no-op except for `bool`) — codegen now honors `omitzero` for String/Int/Uint/Float, and the reflection path honors it for all kinds (empty slice/map/array, nil pointer/interface, zero scalar). The two paths now mean the same thing by the tag. Product impact was exactly one field: logd `WatchEvent.EndReason` now omits when empty, the documented behavior.

- **Item 10 Part B** (untagged empty collection can't reach the wire) — an untagged empty **slice** now emits `[]` (was dropped), matching the reflection path, so a caller can put an explicitly-empty slice on the wire; `omitzero` still drops it. **Scoped to slices deliberately.** Maps are left as-is: the reflection path distinguishes a nil map (`null`) from an empty map (`{}`) — a round-tripping unset-vs-empty distinction — which codegen cannot mirror from `len` alone, so aligning maps is a separate decision. If you want empty maps on the wire from a generated type, say so and I'll take the map case on with that semantics settled.

Cross-path regression tests added for both. All 10 codegen packages in go-tony regenerate cleanly; the logd/docd wire api (`api_gen.go`) is unchanged for 10B (no untagged slice fields), and `o b` on the signadot operator manifests is byte-identical (it encodes ir.Nodes, not Go structs).

**Item 5** (nested generated calls drop `opts...`) is now the only item on this issue not addressed.
