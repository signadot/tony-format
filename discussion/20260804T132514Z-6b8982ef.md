# Plan: step a head document instead of materializing one per conditional write

Same remedy the watch path already took, moved to the CAS path.  `commitMu` is
what makes it safe here, so the fix the CAS correctness bug (b23fdee) needed is
the fix its performance needs too.

## The invariant

    while commitMu is held:  head == ReadStateAt("", currentCommit, nil)

Everything below is in service of that one line.  `evaluateMatches` reads `head`
instead of calling `ReadStateAt`, and the cost per conditional write drops from
O(patches since snapshot) to O(match).

## Shape

`Storage` gains a head document and steps it on every commit:

- **Seed** once, lazily, on the first commit or first conditional read after
  start, from `ReadStateAt("", current, nil)`.  Recovery already pays a full read
  elsewhere, so no new startup cost is required, and seeding lazily keeps a
  process that never uses CAS from building one.
- **Step** inside `commitMu`, where `WriteAndIndex` already runs: after the write
  succeeds, `head = tony.Patch(head, appliedPatch)`.
- **Read** in `evaluateMatches`, replacing the `readState` call at
  `storage/tx/match.go:22` for the baseline case.

Nothing new is built.  `doCommit` already has the merged patch in hand at
`coord.go:369`, and the old code materialized a whole document per conditional
write and discarded it — the same sentence `session.go:751` uses about the
watchers.

## The four things that can go wrong

**1. Stepping from the wrong bytes.**  The read path applies the patch *as
stored* (`patchNodesFromSegments` → `applyPatchesToBase`), while `doCommit` has
`mergedPatch` *before* storage.  `InjectAutoIDs` and `TagPatchRoots` run before
`WriteAndIndex`, so the in-hand form is close, but "close" is not the invariant.
Step from whatever `WriteAndIndex` actually persisted, and if that is awkward to
get back, treat the equivalence test below as the gate rather than assuming.

**2. Aliasing.**  `tony.Patch` clones the *patch* (`patch.go:19`) but not the
doc, and mergeops may reuse doc subtrees, so it is not established that the
previous tree survives a step unchanged.  This is exactly where it would bite the
watchers too, since they keep `prevDoc` alongside `curDoc`.  So: never hand
`head` to a caller that outlives `commitMu`.  `evaluateMatches` only navigates
and matches, both read-only, so the lock scope covers it — but a later caller
must not be allowed to keep the pointer.  Worth an explicit comment on the field
saying so, and worth settling whether `Patch` is functional before relying on it.

**3. Drift.**  A stepped document that silently diverges is worse than a slow
correct one.  Two guards:
   - If a step returns an error, drop `head` to nil and log it.  The next
     conditional read re-seeds from `ReadStateAt`, so the system degrades to
     today's behaviour rather than to a wrong answer.
   - Compare against a recompute when a snapshot is taken.  `createSnapshot`
     already materializes the whole document at that commit, so the comparison is
     nearly free and it is the natural cadence: any drift is caught within one
     snapshot interval, in production, not just in tests.

**4. Memory.**  One more materialized document per storage.  Each baseline
watcher already keeps one, so this is not a new order of cost, but it is a real
one for a large document with no watchers.

## The scoped case, and how much this actually buys

`ReadStateAt` forks on `scopeID != nil` (`storage.go:192`), and a scoped view
cannot be stepped for the reason scoped watchers cannot (`session.go:754-757`): a
scope's writes apply last and shadow baseline stickily, so folding a baseline
patch into a materialized scoped document lets baseline overwrite a leaf the
scope owns.

So scoped CAS keeps recomputing, and **the fix helps only baseline callers**.

`LogdSession.PatchIf` takes no scope — it comes from the session — so which side
verse's reflector lands on is not answerable from the CAS path alone, and it
decides whether this addresses the 40-minute pass in the report or only the
repro.  Worth settling first; it is one question, and it changes whether scoped
overlay stepping (5hmq80f3h12krh1mbsn0) belongs in this work or after it.

## Verification

- **The oracle already exists.**  `TestReadEquivalence_SnapshotVsReference`
  (`storage/read_equivalence_test.go:224`), whose reference branch folds from
  commit 0 via `tony.Patch` and is described at `:26` as *the semantics of
  record*.  Add a third branch: stepped head vs that fold, over a randomized
  commit sequence, crossing at least one snapshot boundary.
- **`cas_test.go` must still pass**, including `-race`: N concurrent PatchIf with
  the same precondition, exactly one commits.  The head is mutated under
  `commitMu`, so `-race` is the check that nothing reads it outside.
- **The attached repro is the benchmark.**  Its prediction is specific and worth
  keeping as the regression: conditional throughput should go flat, tracking the
  unconditional arm, and stop depending on where the run lands on the snapshot
  sawtooth.
- **A drift test**: force a step to fail, assert the next read re-seeds and
  returns the same answer as `ReadStateAt`.

## Staging

1. Settle baseline vs scoped for the real caller.  Everything else is the same
   either way, but it determines what this fixes.
2. Head document on `Storage`: seed, step under `commitMu`, nil-on-error.  No
   reader yet — pure addition, invariant testable on its own against the oracle.
3. Point `evaluateMatches` at it for the baseline case, keeping `ReadStateAt` for
   scoped.  This is the commit that changes behaviour.
4. Snapshot-time drift check.
5. Re-run the repro.

## Not in this

A path-scoped read (`ReadStateAt` honouring `kp`) would help both baseline and
scoped, and `storage.go:184` keeps `kp` in the signature as *"the natural hook
for a future path-scoped read"* — but it also records that using it to pick the
snapshot base broke twice already (bvm163tyh12krwcqcsn0).  Larger, separate, and
not needed for this.
