Fixed by 6464263e (branch issue-2q5art3x): the pid bytes are XORed with 16 bits of a splitmix64 hash of (timestamp, counter). The mask is a function of fields the id keeps, so uniqueness is unchanged and the pid can be recovered.

Characters 3 and 4 of the XIDR still come from the counter's upper bytes, so they stay the same for about 256 ids in a row. For example, one run gave `bntkfcse…`, `bstkf1bd…`, `c1tkfs29…`. After them, the machine id is still a fixed `h12k…`. The stem that used to be ~10 characters long is now 2 characters near the front, with 4 varying characters after them. Mixing the counter (the first option above) would also vary those 2 characters.
