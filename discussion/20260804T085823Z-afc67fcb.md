# Amendment: the encoder round-trip work is a blocker, not a drop

The audit above dropped the old stage 4 and called the encoder bug "not this issue". Half
right: it is not this issue, but it **blocks** this one, so it belongs in this plan rather
than out of it.

Filed as **6fnd2hxeh12ks359e5n0** — *encode: numbers do not round-trip — integral floats
retype, large floats emit unparseable output* — and recorded with
`git issue blocks 6fnd2hxeh v0tp11hmh`.

It turned out to have four faces, not one. Beyond the `1.0 -> 1` retyping already noted
here:

- `k: 1.7976931348623157e308` encodes to a 309-digit integer literal that tony then fails
  to parse. Encode is not total into its own language.
- `-0.0` and `0.0` are `DeepEqual` but hash differently (`ir/node.go:426` compares with
  `!=` where Go says they are equal; `ir/hash.go:50` hashes `math.Float64bits` where the
  sign bit differs). Equal nodes that hash differently matter to anything keyed on `Hash()`.
- `1e400` is refused on input, against `docs/tony.md:10`'s "Valid JSON is valid Tony".

## Why it blocks

Stage 3 here specifies a canonical rendering per notation per output format. That is a
rendering contract for numbers, and it cannot be specified or tested on top of an encoder
whose number rendering is neither injective nor total. `!exp` exists precisely to make
`1e9` survive as `1e9`; today `1e9` renders as `1000000000` and returns as an integer.

It also weakens this plan's stated safety net. `TestNeedsQuoteAgreesWithRoundTrip` is what
keeps `NeedsQuote` honest as the literal rules change, and a round-trip oracle is worth
less while round-tripping is broken for a neighbouring scalar type.

## Revised staging

- **Blocker — 6fnd2hxeh12ks359e5n0.** Encoder number round-trip. Independent session; it
  touches the encoder and `ir` equality/hash, none of which this issue's stages 1 and 2
  touch, so the two can run in parallel until stage 3.
- **Stage 0.** `ir.IsPresentation` / `ir.StripPresentation`, with `!bracket` and `!literal`
  moved onto it. Pure refactor. Independent of the blocker.
- **Stage 1.** Named lexer error (rule 5). Independent of the blocker.
- **Stage 2.** Rules 3 and 4, `NeedsQuote` inverse, round-trip table. Independent of the
  blocker — it changes the string/number boundary, not number rendering.
- **Stage 3.** Radix literals, notation tags, output matrix, YAML-input fix. **Requires the
  blocker to be closed first.**

So only stage 3 actually waits. Stages 0 through 2 — which include the whole k8s surface
that motivated the issue, `100m`, `1Gi`, `30s`, `1.2.3` — can proceed immediately.
