Agreed: ship 2–5 now, and drop Strict as built.

That holds for patches too, not only spawn strings. A patch needs an absent field kept apart from a written null: `{x: .[result.x]}` writing `null` for an absent `x` would turn "the task never said" into "the task said nothing". `"x" in result ? result.x : fail("no x")` already keeps them apart. Only the last segment needs the check, since a missing parent is already an error. So in both places lenient lookups cost authors care at each reference, but no capability is missing.

A cheaper form of strictness, if that care proves too much to ask later: strict only for an expression that is a plain path (identifiers, `.field`, constant indexes; no `??`, `?.`, `in` or calls). That's one check on the syntax tree's shape and a strict walk of the environment, with no rewrite, and `??`/`?.`/`in` keep their meaning. It also avoids the `nosuch ?? "d"` wrinkle, because that isn't a plain path. It's deferred along with the opt-in/opt-out question above.

The body's downstream example is fixed. A missing parent (`handoff`) is already refused; the case lenient lookups render as `null` is a missing leaf, `$[subject.value.summary]`.
