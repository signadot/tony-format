## txpool wired (a926d8b) — multi-mount transactions

docd now owns the txpool (warmed on StartClientTCP, closed on StopClientTCP; the
orphaned pool in `o sys up` removed) and uses it to coordinate multi-participant
transactions.

Model (scott): pre-allocating a TxID is cheap, and a participant joins by writing
to logd with it (write = join, WOL). Flow: baseline client NewTx -> served from
docd's pool (no logd hop; scoped clients forward to logd, since pooled ids are
baseline-scoped, scope captured from hello). Client sends N PatchTx with that
TxID; docd routes each to its controller; each controller joins by writing to
logd with the TxID; logd commits atomically.

Added: libctl.LogdSession.NewTx + PatchTx (additive); controller Handler.Patch
gets PatchParams{TxID}; a logd-backed reference controller.

Constraint discovered/documented: logd dispatches one connection's requests
sequentially and a participant patch blocks until commit, so a multi-participant
tx's participants must be on distinct logd connections. Holds naturally here
(participants route to different controllers = distinct logd sessions; docd
routing is async).

Tests (race-clean): LogdSession two-session atomic commit; end-to-end multi-mount
tx through docd committing atomically.

Known follow-ups (not gaps): scoped multi-mount tx is unsupported (controllers
are baseline-scoped); docd-coordinated patch SPLITTING (one client patch spanning
mounts, auto-split into a tx) is not implemented — the client expresses the tx
explicitly via NewTx + N PatchTx. Pool has no background refill (prefetch-once +
on-demand fetch when empty).
