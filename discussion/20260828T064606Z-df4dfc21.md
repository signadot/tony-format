## it was the classification, and it was insert

`!insert` applied its child as a patch against the DOCUMENT, so a container merged
with the one it landed on:

```
{a: !insert {b: 2}}  over  {}            ->  {a: {b: 2}}
{a: !insert {b: 2}}  over  {a: {c: 9}}   ->  {a: {b: 2, c: 9}}
```

The result depends on what was there. That is the definition of relative, and
`!insert` is the storage vocabulary's flagship entry -- "adds a value; the value is
what results". The docstring was right and the operation was not.

It survived because `MakeDiff` emits `!insert` only when `from == nil`, and merging
with nothing is replacing. A STORE is what reaches the other case: a scope keeps the
delta, baseline moves underneath it, the value that was absent at the write is present
at the read, and the scope's view changes without anyone writing to it -- which is
3xn08cb6h12kr4psg5n0's failure mode reached through an operation the guard permits.

## the fix

`insertOp.Patch` applies its child against ABSENCE rather than against the document.
The child is still applied as a patch, so `!insert(t)` still means "insert this,
tagged !t" and `keyed_list.go`'s use is unchanged -- that one was already applying
against an absent document by hand.

The whole suite passes with it, so nothing in the tree relied on the merge.

## and it closes the tag half too

My earlier comment said `!rmtag(a).addtag(b)` "is not what retag does", measured at
6 -> 85 round-trip failures. That was wrong. The rewrite was tried while a container
answered whole still merged, and the two faults together read as one. With `!insert`
fixed, the same rewrite is exact.

`DiffAbsolute` now answers with `!insert` for a whole-value replacement, and
`absoluteTags` rewrites `!retag(a,b)` into the two halves. Over the property
generator, 500 seeds:

```
vocabulary   0 failures   -- !replace, !strdiff, !arraydiff and !retag all absent
round trip   0 failures   -- Patch(a, DiffAbsolute(a,b)) == b
```

Both were 6 and 5 respectively before. TestDiffAbsoluteRoundTrip is unskipped.
