Baseline is flat, which is phase 3b working: a write is verified by a bounded read at each
site it states something at, so it no longer folds a document. The scoped column is the
issue, and the shape has CHANGED rather than closed. This issue recorded the scoped
no-interleaving case as FLAT at ~370us, because a scope kept its own document and stepped
it, and only interleaved baseline traffic invalidated it. Phase 3b deleted that kept
document along with the baseline head (scope_head.go is gone), so there is nothing to
invalidate and nothing to reuse: every scoped write now pays the replay, whether or not
baseline committed in between.

The mechanism is that a scoped read replays the scope's own patches at the path FROM COMMIT
0, and no snapshot shortens that: snapshotPath reads with scopeID nil, so path snapshots are
baseline's. Phase 7's scope compaction (9a54d21) is the only thing that bounds it, and only
past the cutoff and only where a later entry dominates -- neither applies to a scope actively
writing.

So this stays open, and it is now the same defect as 9b2vpggxh12ks0qde5n0 seen from the write
side. Whether the change is net better or worse depends on traffic shape -- uniform cost
instead of cheap-until-interleaved -- but the linearity is unaddressed either way.
