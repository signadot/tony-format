  - null / missing key: REFUSED at the write (decision 1 as recommended)
  - the stored object carries NO tag -- passesThrough reads any non-presentation label as an operator, so a tag would cost every element write its spine at the array; the schema says both things the tag would. element_identity.md amended.

  - identity is declared before an array is written, and never lost or changed (identityChangeAllowed). Built, tested, not exercised by any live store.

One thing worth knowing for phase 3: every read now consults the schema (to raise), which a resolver that itself reads can re-enter -- tick_test's probe did exactly that and now guards itself.
