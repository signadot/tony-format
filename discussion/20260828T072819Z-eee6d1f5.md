## the fold was in lowerWrite, not in the read path

The coercion that turned absence into null was `lowerWrite`'s own:

```go
if next == nil {
    next = ir.Null()
}
```

`api.NextState` answers nil for a write that removes everything, and coercing it stored
"the document is null" for a write that said "there is no document". A root `!delete`
then read back as null where the same write kept as sent read back as nothing.

The two paths now store the same thing and read back the same:

```
kept as sent   !delete.logd-patch-root null           READ <nil>
lowered        !delete.logd-patch-root a: 1           READ <nil>
```

`libdiff.MakeDiff(base, nil)` is the delta, which carries the old value under the
`!delete` -- see below for why that matters.

## the value under a !delete is load-bearing

Tried emptying it, on the theory that a stored delta is replayed rather than reversed
so the old subtree is dead weight. It is not: `IndexPatch` walks the stored delta, and
the paths under a `!delete` are how the index records what went away.

`TestAbsentPathAnswersAsTheDocumentWould/verse.gone.zz` catches it immediately --
"answered from the index: false, want true", the absent read falling back to a full
document read because the index no longer knows the path existed. Reverted.

## where the differential stands

11 failing tests at the start, 2 now, and they are the same two:
`TestHeadEquivalence_SteppedVsReference` and `TestReadEquivalence_SnapshotVsReference`,
both equivalence checks between the stepped head and a full read.

What is left in them, separated:

- 4 value divergences, every one a `!delete` at a NON-ROOT path -- `a.b <- !delete`,
  `d.e <- !delete`, `a.b.c <- !delete`. The head applies the delete and the replay does
  not, so the stored delta is not deleting on the way back in. Root deletes are fixed;
  these are not.
- 20 snapshot-boundary cases, "the snapshot check dropped the head", with no error --
  the head disagrees with a full read across a snapshot.

Both are about a lowered delta re-materializing differently from the patch it replaced,
which is one question rather than two.
