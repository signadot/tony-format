The root cause is the superfluous body, and it is an inconsistency of one request
against its siblings rather than a subtlety. Encoded side by side:

    patch  {patch: {data: {k: v} path: a.b}}
    watch  {watch: {noInit: false path: a.b}}
    match  {match: {body: {data: {k: v} path: a.b} commit: 7}}

PatchRequest EMBEDS PathData, so path and data sit directly under the operation, and
so does watch. MatchRequest names it `Body PathData`, so they sit one level down. The
name reads as sensible because the RESPONSE has a body -- but a response's body is the
answer, not a wrapper, so the same word means two things one message apart.

THE SHAPE I WOULD PICK. Embed PathData in MatchRequest as PatchRequest does:

    {match: {path: "a.b", data: <pattern>, commit: 7}}

Then path is in the same place in all three, and commit sits beside it as txId and
timeout do for a patch. Nothing is lost: MatchRequest is exactly (PathData, Commit).

WHY IT WANTS THE STRICT CHECK IN THE SAME CHANGE, not after. The dangerous direction is
a client one version ahead of a server: a new client sends {match: {path: ...}} to an
old server, the old server does not know the field, and it reads the ROOT and answers
as though asked. That is this issue's failure mode arriving through an upgrade. With
unknown-field refusal in place first, the same mismatch is an error naming the field.

So: refuse unknown fields, then flatten -- or both together and roll the server before
the clients. If logd, docd and verse always deploy together, one step is fine.

WHO BUILDS THESE. MatchRequest is constructed in Go in three places -- libctl's client,
docd's compose_read and logdread -- so a recompile carries them. What is left is hand
written requests: `o system logd session`, anything external, and the tests and probes
that type the wire form directly (mine typed the wrong one for most of a day).

Happy to implement it as one change: embed PathData in MatchRequest, refuse unknown
fields in the request envelope (stopping at the boundary with client data), and update
the three constructors and the session tests.
