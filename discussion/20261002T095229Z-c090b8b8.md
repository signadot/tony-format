Fixed in dd421a2c, on branch `issue-f43dnqpk`. It did not get complicated.

**The fix.** `provenAbsent` (storage/cursor.go) no longer answers "never written" once compaction has dropped a baseline patch. The read then goes to the snapshot it seeks to, which is what it did before the restart, when the index still had the path's node in memory. One condition covers the three callers: `Read`, `Children` and the kind lookup a precondition uses.

**The condition is the baseline floor**, so the branch is stacked on `issue-cpqj2tf6`, which adds it. On main alone the replay floor would serve, more conservatively.

**Test.** `TestReplayFloor_StateBelowFloorStillReadable` now reads every key at its own path and lists the root, before and after a reopen. Without the fix, the two keys whose only patches were dropped read as absent after the reopen. The reproduction in this issue passes. The full `system/` suite passes (155s).

**Cost, measured** on a compacted store of 20,000 entities under one container:

| read | with the index's proof | without it |
|---|---|---|
| absent, top level | under 1µs | 23µs |
| absent, under the container | 278µs | 39µs |
| present (for scale) | | 49µs |

The proof was slower under the wide container because it scans the container's child nodes to show it is an object.

**Not done:** a narrower rule that keeps the proof where it is still sound (the index recording which paths a snapshot holds). At these costs it does not look needed.
