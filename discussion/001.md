## Problem

docd single-routes reads. In routeFor (client_session.go), a read (Match/Watch)
whose kpath is an ANCESTOR of one or more live mounts routes only to logd and is
blind to every mounted subtree; path=="" and any intermediate ancestor both fall
to destLogd because LookupPrefix only matches at-or-below a mount
(hasFieldPrefix(opFields, mountFields)). The write side already composes the
symmetric case via splitPatch — read composition was left naive.

Scope note: whole-tree/root watches are out of design scope ("too big a pipe").
Watches are scoped subtrees, so read composition applies to ancestor reads that
contain a mount, not a firehose over the root.

## Design (decided)

### Match composition
For a read at ancestor kpath P, reuse the splitPatch partition logic:
- base -> Match P on logd (unmounted content only),
- each live mount Mi with P prefix-of Mi -> Match on that controller,
- merge into one document rooted at P (deeper mounts overlay shallower where
  nested); return ONE MatchResult.
- Tombstoned mount in range -> that subtree errors controller_unavailable
  (consistent with the write path), no silent fallback to logd.
- Fan-out reads under a registry read-lock so the target set is a consistent
  snapshot.

### Watch composition
Extend the existing client-watch-id -> backend-watch multiplex (UnwatchRequest.
WatchID) from one mount to base + N mounts: subscribe logd (base region) + each
live overlapping controller, fan events onto the single client watch id, Unwatch
all on client unwatch/close.

Watch membership is FIXED for the watch's lifetime — docd emits no synthetic
snapshot/teardown deltas. Membership changes are handled by mount/unmount
coordination instead (below), and a forced reader re-watches (its LogdSession
re-watch path) to re-compose against the new set.

### Mount/unmount coordination (writer-priority)
- Mount and graceful-unmount are WRITERS on a path-scoped registry lock with
  writer priority: a pending op immediately blocks NEW overlapping watches from
  starting (no reader-starvation), then waits for existing overlapping watches
  (kpath overlaps mount path — prefix either way) to drain.
- force_after timeout, 0 = infinity (wait forever, never force). On timeout,
  remaining overlapping watches are errored with membership_changed and the op
  proceeds.
- Graceful unmount becomes an explicit request (can block / force_after). A
  controller CRASH is involuntary -> stays the existing tombstone ->
  controller_unavailable path.

### Wire surface (additive)
- force_after field on the MOUNT request.
- an explicit graceful-unmount request.
- membership_changed error code.

## Plan
1. Match composition (fully correct, low-risk) — land first.
2. Mount/unmount writer-priority coordination + force_after.
3. Watch composition (static-per-lifetime membership) on top of (2).
