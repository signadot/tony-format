Fixed in 8b4bbba (libctl) and 2673a7b (docd).

libctl: doPatch returns *api.PatchResult instead of discarding it, and Patch/PatchIf/PatchTx/PatchTxIf/PatchWith all return it — the breaking form, not the additive one, since every in-repo caller was a test and verse has two call sites. Reused the wire type rather than declaring a libctl twin: libctl already exposes api.PathData and api.WatchEvent in these same signatures, and reuse keeps the client and the controller-forwarding path conversion-free.

Handler.Patch returns *api.PatchResult too, so controller.go's Commit-left-zero is gone: handlePatch forwards the handler's result whole. A logd-backed controller hands PatchWith's result straight back; a self-backed one leaves Commit zero rather than invent one from its own timeline, the same reason Match cannot honor a historical read.

docd: the gap found while fixing the above — coordinatePatch answered a multi-mount write with the commit and nil data, so ids were unreachable whenever a document happened to span two mounts. joinPatchResults is splitPatch's inverse for result data: nest each participant's report at the path it wrote, merge along the spine, answer relative to the client's patch path. A participant reporting no data leaves a hole rather than voiding the result.

Tests: TestLogdSession_PatchReportsCommit asserts the returned commit equals the one a watch reports for the same write (the property asked for here). The two transaction tests assert every participant is told the same commit, TestDocd_MultiMountTransaction through docd and two controllers. TestJoinPatchResults_InvertsSplit round-trips the split cases; TestDocd_SplitPatchReportsStoredData asserts a three-participant write through docd reports the same data as the identical write against plain logd.
