Fixed in 3a8656a. Broadcast now delivers via a non-blocking send to each watcher's buffered Events channel (fail-on-full instead of a 5s per-watcher wait), so it never blocks the committing goroutine — unrelated writers' commit acks and the session heartbeat are no longer held hostage by a slow consumer. Per-watcher buffer bumped 100->1024 to absorb bursts in place of the time grace. New test asserts non-blocking + no starvation of a healthy watcher; existing slow/fast tests still pass; -race clean. Note: fan-out is still on the committing goroutine but returns immediately; a fully async ordered worker was considered but the per-watcher buffered channel already provides ordered async delivery.
