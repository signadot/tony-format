Three more, found applying codegen to verse's `process` package. Together with items 2-4 above
they are why verse ends up not using `tony-codegen` at all — see the note at the end.

## 7. `map[string]any` is unsupported by codegen (but fine via reflection)

```go
//tony:schemagen=verse-pattern,notag
type Pattern struct {
    Fields map[string]any `tony:"field=fields,omitzero"`
}
```

```
failed to generate ToTonyIR() for "Pattern": failed to generate field conversion for
"Fields": unsupported map value type interface {}: unsupported primitive type: interface
```

`gomap`'s reflection path handles `map[string]any` in both directions, so this is a codegen-only
gap. It matters because `map[string]any` is the natural Go spelling for "an arbitrary document
fragment" — which in a tony-shaped program is a very common field type. verse has it in
`Pattern.Fields`, `launch.Provider.Match` and `trigger.Action.Set`.

At minimum this should emit the same code the reflection path takes; `*ir.Node` would be the
nicer target but is a bigger change for a caller.

## 8. A named SCALAR type resolves to `int`, silently, wherever TextMarshaler is not consulted

Extends item 3 (unresolvable types) to non-struct types, where there is no annotation that helps.

```go
type Verb string          // process/effect.go
type Status string
type ResourceKind string

//tony:schemagen=verse-gate-match,notag
type GateMatch struct {
    Verbs []Verb `tony:"field=verbs,omitzero"`
}
```

generates

```go
slice[i] = ir.FromInt(int64(v))     // v is a Verb, i.e. a string
```

```
cannot convert v (variable of string type Verb) to type int64
cannot use elem (variable of type int) as Verb value in assignment
```

Note `generatePrimitiveToIR` would do the right thing here — it switches on `Kind()`, and
`reflect.String` maps to `ir.FromString`. The bug is upstream of it: the element type was
resolved to `int` because it could not be resolved at all, and `int` is the fallback. So the
generated code is not merely suboptimal, it names the wrong Kind.

**Two things make this hard to work around:**

- `//tony:schemagen=` on a named string type is **ignored** — `ExtractTypes` only collects
  structs, so there is no way to make such a type resolvable.
- `MarshalText`/`UnmarshalText` fixes it **only for a direct struct field**, not for a slice
  element. Adding them to `Status` fixed `Instance.Status`, and to `ResourceKind` fixed
  `ResourcePred.Kind` — but `GateMatch.Verbs []Verb` still generates `int64`, because the slice
  path never consults TextMarshaler.

**Workaround in verse:** `Mode`, `Status`, `ResourceKind` and `Verb` all gained
`MarshalText`/`UnmarshalText`. That is defensible on its own merits, but three of the four were
added purely for this, and it does not fix the slice case at all.

**Suggested fix:** resolve named types by their underlying kind when no schema is found (a named
string is a string), rather than falling back to `int`; and consult TextMarshaler in the slice
and map element paths as well as the field path.

## 9. The cumulative effect: codegen is unusable for this codebase

Not a separate defect — the consequence of 2, 3, 4, 7 and 8 composing, recorded because it is
the actual outcome.

Working through verse's packages:

| package | blocker |
|---|---|
| `entity` | `Pattern.Fields map[string]any` (7) |
| `launch` | `Provider.Match map[string]any` (7); `Spec` references `Provider`, so 4 spreads it |
| `process` | `GateMatch.Verbs []Verb` (8); `Gate` references `GateMatch`, so 4 spreads it to `Vector`, and 3 makes the failure a build error rather than a diagnostic |
| `trigger` | `Match` is a named map (2); hand-written codecs everywhere, so 4 applies |

In each case one unsupported field type propagates to every type that references it, because
there is no way to say "this type has its own codec, just call it" (item 4). A single
`map[string]any` or `[]NamedString` field therefore takes a whole package out of codegen.

verse has instead implemented `omitzero` once, over `gomap`'s reflection path, in its own
`codec` package — about 100 lines that work for every type, versus roughly 700 lines of
hand-written `ToTonyIR`/`FromTonyIR` boilerplate to work around the above. `tony-codegen` is
consequently not used in verse at all today. Items 7 and 8 are the two that would most change
that: between them they cover every blocker in the table except `trigger`, which has genuine
custom grammar and would stay hand-written regardless.
