-b Implemented on branch `issue-7f8rsk22` as `!raw`, two commits.

## Decisions

**1, 2 -- recursive, consumed at apply.** As asked. `!raw` returns its child
verbatim, so nothing beneath it is interpreted because the subtree is never
walked as a patch at all, and the tag is consumed so the value lands with its
own tags intact. A `!raw` nested under a `!raw` is therefore data like anything
else beneath it -- which is what makes the replay story work: the stored patch
keeps its own `!raw` and escapes again.

**3 -- match.** `!raw X` means "this is X" in both directions. In a pattern it
compares literally: tags compared rather than evaluated, and *exact* -- same
field set, same length, `null` means `null` -- rather than the partial object
match of an ordinary pattern. That exactness is what makes it the dual of the
patch side rather than a second, weaker thing. It composes instead of taking
over, so you get literal comparison exactly where you put a `!raw`:

    doc     rule: {id: !glob "hotfix-*", patch: {tmp: !delete null}, stage: open}

    rule: {id: !raw.glob "hotfix-*"}          true
    rule: {id: !raw.glob "other-*"}           false
    rule: {patch: !raw {tmp: !delete null}}   true
    rule: !raw {id: !glob "hotfix-*"}         false -- rule has other fields too

Formatting-only tags (`!bracket`) and comments are ignored, so a value compares
equal to itself across an encode/parse round trip.

**5 -- RejectUnsafe.** Unaffected; `!raw` executes nothing and is not Unsafe,
whatever the data it stores happens to name. There is a test storing a `!pipe`
under `RejectUnsafe(true)`.

**4 -- diff.** You were right to look there, and it was worse than for
operators alone. `Diff` now emits `!insert.raw` for a value carrying an operator
tag anywhere beneath it, and `Reverse` stops at a `!raw` rather than rewriting
the operation names inside it, which are the document's values.

But the invariant `Patch(a, Diff(a, b)) == b` was already broken for *tagged
values in general*, which is why your `Diff` -> `Patch` gave `missing tag label`
on a plain `{rule: {id: "x"}}` -- that was not your misuse. `MakeDiff` writes an
inserted or deleted value's tag as an argument without its `!`, and `insert` and
`delete` compared and installed the bare label as if it were a tag, so *every*
diff which inserted or deleted a tagged value produced an unappliable patch --
including every insert of a bracketed object, `!insert(bracket)`. `CheckTag`
rejected every tag it was given. `!strdiff` dropped the string's tag.
`!addtag`/`!rmtag`/`!retag` discarded everything they decorate whenever both the
tag and the value changed. A field-removing patch was applied twice. A `!delete`
under `!key(...)` left a nil for `ir.FromSlice` to dereference, and patching a
keyed list dropped its `!key`. All fixed, in the commit message's list.

`TestDiffRoundTrip` and `TestDiffTestsRoundTrip` now hold the invariant by
APPLYING the diff -- the second over the corpus `TestDiff` had only ever checked
the text of.
