## Participant count formula (scott)

For a docd-coordinated multi-mount transaction, the participant count is:

    participants = (number of participating controllers) + 1

The +1 is the docd<->logd link: docd itself joins the transaction. So a patch
spanning 2 controllers is a 3-participant tx (2 controllers + docd).

Implications for this work:
- When docd splits a patch across N controllers, it allocates the pooled TxID
  with participants = N + 1 and itself participates on its logd link.
- The txpool prefetch/backfill self-corrects to the counts actually requested
  (each Get triggers a refill for that exact count), so no prefetch tuning is
  required up front — but the natural hot counts will be 2, 3, 4, ... (1, 2, 3
  controllers).

Note: the current explicit-client path (LogdSession.NewTx + N PatchTx) has no
docd participant — the client coordinates and docd only routes — so those txns
use participants = number of controllers, with no +1. The +1 is specific to the
docd-coordinated model this issue defines.
