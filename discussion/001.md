Fixed in 7a04f33.

The original symptom (an `isZeroValue` helper spelled `map[string]struct` — the
bare keyword) was already gone; the signature now resolves correctly. But the
field still generated non-compiling code, the symptom just moved: codegen emitted

    node, err = s.Repos.ToTonyIR()      // map[string]RepoConfig has no ToTonyIR
    s.Repos.FromTonyIR(fieldNode)        // ...nor FromTonyIR

Root cause: `DispatchViaMethod` fired for the field because its resolved TypeName
carried the VALUE type's name (RepoConfig), which has a generated codec — but the
field's DECLARED type is an unnamed `map[...]` literal, which has no method of its
own. Fix gates DispatchViaMethod on the declared type being a named type reference
(ast.Ident/SelectorExpr like `type Match map[string]any`), not a composite literal.
An unnamed map now falls through to the reflect.Map path, which iterates and
dispatches per value to each struct's generated codec.

Added testdata/mapstruct + a round-trip test (populate a map[string]RepoConfig,
ToTonyIR, FromTonyIR, assert values survive). No committed generated output changed,
so item 2's named-map dispatch (f69agjyeh12ks) is preserved. Workaround (drop the
tag, let reflection handle it) is no longer needed.
