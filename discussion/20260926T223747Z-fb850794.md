`issue_watch` is in and does what the body asked for: a blocking watch an agent runs in the background, answering on change with a cursor so nothing is missed between calls. Used from Claude Code on 2026-09-27 to follow one issue.

One scope is missing: **a repository.** A watch takes ids, a label, or neither, and "neither" is every issue in every served repository. There is no `repo`. So "watch everything on verse" in a session serving verse, tony-format, signadot and libconnect wakes on any change in any of the four — on a busy repository like tony-format, a steady stream of wake-ups for changes the caller will throw away. The caller can filter by the repo each change names and call again with the cursor, and nothing is lost, but the waiting is no longer quiet, which is the point of a watch.

Ask: a `repo` parameter on `issue_watch` (repeatable, or a list), scoping the watch to those repositories' issues, alongside ids and label as the other scopes. `issue_list`, `issue_create`, `issue_push` and `issue_pull` already take `repo`, so it would read the same way.
