## measured: the store already answers nil for absence, and lowering turns it into null

The recollection that a fresh store returns null does not hold at this layer. Probed
directly, with lowering off:

```
fresh store, commit 0:      <nil>
after a root !delete:       <nil>
a path never written:       <nil>
NextState(base, !delete):   <nil>
```

Absence is already distinct from null everywhere the store answers. With every write
lowered, the same probe:

```
fresh store, commit 0:      <nil>
after a root !delete:       Null null      <- was <nil>
a path never written:       Null null      <- was <nil>
```

So the two representations of ONE write disagree about absence. Stored as the client
sent it, a root `!delete` leaves nothing; stored as a lowered delta with the same
effect, it leaves null. That is what `TestHeadEquivalence_SteppedVsReference` reports
as "head: <nil>, want: null": the stepped head kept the absence `api.NextState`
answered with, and the read replayed the delta and folded it to null.

Note the second row: a path NEVER WRITTEN also changes. So this is not confined to
deletes -- it is the read path's empty-base fold, which `verifyApplies` names in its
own comment ("an empty document reads back as nil, and null is what the read path's
own empty-base branch folds onto"). Lowering just makes the fold reachable where it
was not before.

## what this changes about the fix

Making absence a first-class answer is the coherent direction, and the place to make
it is the FOLD rather than the read of a fresh store, which already answers nil. Until
then the invariant to hold is narrower and testable: a write stored as a lowered delta
must read back the same as the same write stored as sent, absence included.
