Decided (de428863): the second shape rather than the first. `ext add` does not refuse a directory, because `relate`, `blocks` and `duplicate` across the set give the other repository's directory themselves, and a set of repositories with no remotes (offline, or the tests) has nothing else to give. Instead the shared record holds the directory's origin and the directory stays in this clone's git config, `git-issue.source.<source>.path`; a directory with no origin is recorded as it is, and `ext add` and `ext list` say only this machine can reach it. No `--local` flag: nothing needs one once the directory is kept locally by default.

Push already carried a changed sources ref (ApplyCarriedPushes sends an Ahead source; TestSyncCarriesMirrors covers the refresh being carried on). `ext add` now says so, and says what it replaced.

A clone that already holds a path in its shared record, as verse did, shows it in `ext list` marked as one machine's, and the pull's "could not be reached" line names `refs/git-issues/v1/sources/<source>` as where the url came from. The repair is the same `ext add` with the url, and a push.
