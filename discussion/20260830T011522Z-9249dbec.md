Fixed in 6f3bd07, in the tag ops rather than by stripping the marker before merge as I suggested above.

The suggestion in the report was wrong in one respect and Scott caught it: I claimed 'a trailing label never comes from the diff', and reasoned from that toward treating any null child as 'no value change'. But `!retag(a,b).insert` is a perfectly good composition, and `!retag(a,b).insert null` inserts a null and means it. Measured before changing anything:

    !retag(bracket,flow).insert 5              -> !flow 5           the insert runs
    !retag(bracket,flow).insert null           -> !flow null        the insert runs
    !addtag(x).delete null                     -> <nil>             the delete runs
    !retag(bracket,flow) null                  -> !flow {k1:5 k2:16}  value kept
    !retag(bracket,flow).logd-patch-root null  -> !flow null        THE BUG

So the discriminator is whether an OPERATION trails the tag op, not whether anything does. patchUnderTagDiff now keeps the document when the child is null and its chain names no registered operation, and applies it otherwise. Both halves are pinned, and the over-broad version fails the second test on exactly the two cases above.

The claim about diffs does survive, in the narrower form it was needed in: a diff composes the tag op LAST, after the value's own tags (libdiff/object.go's mkTagDiff caller), and a value that BECOMES null is emitted as !replace rather than as a tag op over a null. Measured over ten from/to pairs: every diff-produced tag op has an empty child tag. So a label trailing one is foreign -- but foreign is not the same as inert, which is what the counterexample shows.

What is NOT done, and is still the deeper point: a marker inside an operator's tag chain is a label in the patch's own grammar. This makes the tag ops answer correctly whatever shares their chain, rather than keeping logd's marker out of that chain. The read-side decline in projectPatchesAt (1xnezrpkh12ksavvjdn0) is left in place as insurance for any future op with the same shape -- 16 declines in 23115 narrowed reads, so it costs nothing to keep.
