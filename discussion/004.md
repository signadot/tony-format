Design conclusion (how to fix, grounded in code):

Keying is DATA-CARRIED convention: patches arrive with !key(field) in the data.
The schema resolver only feeds the INDEX (index.IndexPatch(..., schema, ...)); the
read applier calls plain tony.Patch with no schema context (processor.go:97,227),
so schema-as-keyed-merge was never realized. => the merge is schema-unaware.

Consequence: storage MATERIALIZES ops. createSnapshot -> ApplyPatches -> tony.Patch,
and keyedListOp.Patch returns a plain ir.FromSlice(dst) with no op tag. So a scope
SNAPSHOT stores a resolved array; the !key is gone. Re-applying that materialized
array onto a changed baseline falls into the default positional min-length array
merge (patch.go:85) -> truncates/misaligns. A materialized scope overlay is unsound
for !key.

=> The scope layer must be OP-PRESERVING. Fix:
  scoped_read(kp, commit) = baseline_read(kp, commit), then the scope's OWN patches
  (verbatim, ops intact) replayed on top via tony.Patch.
This reuses tony.Patch (no divergence) and makes !key durable for free: replaying a
scope's !key patch onto an updated baseline yields the identity-merged union
(baseline's new keyed items AND the scope's). baseline_state may stay materialized
(baseline snapshot fine); only the scope layer must be raw patches.

Plan:
- Read: tony.Patch(baseline_state, scope-only patches <= commit).
- Un-materialize scope snapshots (they are the defect). Scope overlay = op-preserving
  patch log; compaction of it needs op-preserving patch COMPOSITION -> deferred
  (keep the scope patch log; unbounded only for the scope's lifetime, fine for
  ephemeral sandbox scopes).
- Watch: recompute the scoped value at the touched path and diff vs last emitted;
  raw baseline-delta forwarding is unsound under !key.
- Tests: the four read cases, a !key durability case, the scoped watch stream.
