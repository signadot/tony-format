## Coherence review against prior designs

Checked the plan against: docs/tonyapi/{design,controllers,process-controller-example}.md,
go-tony/docs/dual-proxy-architecture.md, plus content-federation.md and the MOUNT /
Async-Controller issues.

### Confirmed coherent
- Reads route through controllers. controllers.md ("controller handles MATCH for its
  mount") and especially process-controller-example.md (proc-controller answers MATCH
  by reading /proc live, stores only launch/kill events, does NOT warehouse live state
  in logd) validate the reads-through-controller correction. My original "MATCH ->
  passthrough to logd" was the incoherent line; already fixed.
- WATCH is a first-class controller op emitting diffs (both docs).
- Controller-initiated MOUNT + schema contribution composed at /.meta/schema.
- Participant-count transactions: docd requests tx ID from logd with participant count
  (controllers.md) — already partly built (txpool + logd NewTx/TxID).
- docd is a router/coordinator; controllers own logd access (dual-proxy: "docd ->
  Controllers -> logd"; docd/controllers "not yet implemented").

### Divergences to reconcile

D1 (important) — docd is a PURE data-plane router, not a logd read/watch passthrough.
Components A and D above gave docd a logd client for read/watch passthrough on
non-mounted paths and watch fan-out. Prior design assigns ALL state access to
controllers ("controllers are the ONLY components that communicate with logd"; for
WATCH "controllers watch logd directly", docd just registers + forwards). So docd's
logd connection is for tx-ID coordination (txpool) + optional virtual-doc cache ONLY.
=> Drop docd-side logd read/watch passthrough. If raw logd-backed data without a
bespoke controller is ever wanted, add an explicit built-in "passthrough controller",
not a docd special case. Simpler and cuts M1 scope. This supersedes comment #001's
"non-mounted paths served from logd directly".

D2 — transport: TCP-only supersedes the older local stdin/stdout (spawned) controller
model in controllers.md/design.md. The MOUNT issue already decided "all controllers
connect via TCP, no stdio, no spawning." Our plan follows the newer decision. Note so
the stdin/stdout model is not resurrected.

D3 — framing: the logd session protocol (newline Tony over TCP) supersedes the older
HTTP/!apiop framing in the tonyapi docs. Scope consequence: M1 uses logd's simpler
Match(path)/Patch(path,data) ops, NOT the full !apiop match-pattern/field-selection
model or cross-controller MATCH composition — those are a later, larger, controller-
interpreted surface.

D4/D5 — deferred but blessed by prior design: docd virtual-doc cache (our #3 defers)
and docd-orchestrated cross-controller MATCH + multi-mount tx (our M3). Both consistent.

### Net
Plan is coherent after the reads-through-controllers correction. The prior corpus lets
us CUT M1 scope: docd needs no logd read/watch path (D1). Governing note: on transport
(D2) and framing (D3) the newer logd/MOUNT decisions govern the older tonyapi docs.
