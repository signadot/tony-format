Done in 038a616.

`git issue serve` is registered in root.go, documented in usageText and the
README, and covered by table-driven tests over a temp repo. The two calls this
issue left open:

- **Markdown: goldmark**, renderer left at its default. With Unsafe off it
  replaces raw HTML with a placeholder and refuses `javascript:` targets. It was
  already in the build graph as an indirect dep of `golang.org/x/tools`, so
  taking it directly adds no new module -- go.mod gains one line moving it to
  the direct block (v1.4.13 -> v1.7.13).
- **Caching: yes, on GetRefCommit**, but the commit alone is *not* a sufficient
  token and the first cut was wrong about this. Closing an issue moves the ref
  without rewriting the commit, so a cached page kept serving `open` after the
  close. The token is `commit + "." + status`; the index uses a digest over
  every `ref commit` pair. Same value is the ETag.

Read-only held. No write endpoints, no close/comment affordance.

Three followups, each worth its own issue rather than reopening this one:

1. **serve half-binds when the host resolves to more than one address.**
   `net.Listen("tcp", "localhost:8080")` takes one of ::1 / 127.0.0.1 and says
   nothing about the other. Hit in practice on the first run: an unrelated
   process held IPv6 `*:8080`, serve bound IPv4 `127.0.0.1:8080`, and the
   browser followed `localhost` to ::1 and got that process's 404. serve was
   working the whole time and gave no hint. The startup line prints the address
   actually bound, which is true but too quiet. Fix is to bind every address the
   host resolves to and fail loudly naming the conflict instead of quietly
   taking whichever half is free.

2. **Merge semantics for issue refs.** This is the real blocker behind serve
   being read-only, and it is a prerequisite for any write surface anywhere --
   not just the web one. Sync is `+refs/issues/*:refs/issues/*` in both
   directions with no merge, so any second writer is a lost update. Worth
   stating as its own problem so the constraint stops being re-derived every
   time someone wants a button.

3. **Angle brackets in issue text render as goldmark's omitted-HTML
   placeholder.** `refs/issues/<xidr>` in a description comes out as
   `refs/issues/<!-- raw HTML omitted -->`. That is markdown behaving correctly
   and the safe thing to do, but it is noisy in exactly the prose this repo
   writes -- this issue's own body hits it four times. Worth deciding whether to
   pre-escape lone angle brackets that cannot be a tag, which keeps the text
   readable without turning Unsafe on.
