One invariant -- one element, one name, the index stays a trie of names -- and the rest derived from it. (f=v) and <{...}> are names, sorted, canonical; a partial or secondary binding is WILD, resolves to a set of names, and never keys the trie. Several !logd-key on one array = one composite identity. Keys are immutable (a rename has no reading compatible with an immutable log). !logd-key/!logd-auto-id REPLACE positional identity, so a keyed array reorders without touching an index node.

One fork open with a recommendation, not decided: key fields first in the lowered form (recommended, one-pass naming) vs. name-at-close with a pending subtree per open element.
