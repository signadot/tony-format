Plan (branch issue-cn1n32yp). Field is `author`, a string, opaque to logd. Protocol moves to 3.

## Wire format

```tony
{hello: {clientId: verse, protocol: 3, scope: s, author: alice}}   # session default
{patch: {path: p, data: d, match: {...}, txId: n, timeout: "5s", author: bob}}  # this write's
{event: {commit: 7 path: p patch: {...} author: bob}}              # every delta event, live and replay
```

- A write's author is `patch.author` if present, else the session's `hello.author`, else none.
  Resolved by the first server that commits it or splits it (logd, or docd for a write it
  decomposes). Empty string is none; `omitzero` on the wire.
- `event` carries it on delta events only. A `state` event is many commits and has none.
  A `match` result has none (out of scope; a reader who wants who-wrote-what watches or replays).
- `newtx` takes no author: a transaction's author comes from its participants.
- `result: {patch: ...}` is unchanged.
- Protocol 3. A client at 3 against a server at 2 is refused at hello, which is what closes
  the "author sent, author dropped, looks kept" hazard. A protocol-0 client is still accepted
  and its writes have no author.

## Multi-participant transactions: one commit, one author

Each participant's resolved author is recorded on its `PatcherData` (the log keeps the
per-participant record). The commit's author, on the entry, the notification and the event,
is the one every participant resolved to. A participant whose resolved author differs from
one already in the transaction, none-vs-some included, is refused at the join with
`tx_author_mismatch`, next to `tx_scope_mismatch`. There is no co-authored commit; the rule
is stated rather than hedged with an empty author on disagreement.

Consequences for a client:
- A client `newtx` + N patches must carry the same author on every participant (or rely on
  one hello default across them). Through docd, each participant is routed to its
  controller, which must relay the author to its logd write, or the join is refused.
- docd stamps `author` explicitly on every patch it builds on a client's behalf (base
  participant, controller hop), like it stamps `scope`. libctl's `PatchParams` gains
  `Author` and a logd-backed controller passes it through `PatchWith`.

## Caveats

- Unauthenticated: logd stores what it is told. Whoever multiplexes principals onto one
  session is trusted to stamp them correctly.
- Schema commits and snapshots carry no author (not asked; a follow-up if wanted).
- Stored on `dlog.Entry` beside `Timestamp`; compaction rewrites entries whole, so it survives.

## Files

- api: `Hello.Author`, `PatchRequest.Author`, `WatchEvent.Author`, `ErrCodeTxAuthorMismatch`, `ProtocolVersion = 3`; regenerate.
- storage: `tx.PatcherData.Author`, `dlog.Entry.Author`, `CommitNotification.Author` (commit path and `Deltas` replay); mismatch check in `NewPatcher`.
- server: resolve in `handlePatch`, session default from hello, stamp on `patchEvent`.
- docd: `writeBaseParticipant`, `coordinatePatch`, resolve against the client's hello.
- libctl: `LogdSession` hello author, `PatchOpts.Author`, `PatchParams.Author`; `WatchEvent.Author` surfaces as is.
- docs/logd/session.md: protocol 3, the fields above, `tx_author_mismatch`.

Verse side: nothing moves. Set `author` per patch from `entity.Write`'s principal; a
session per principal can use the hello default instead.
