-m Correction to the previous comment: "prerequisite 1 and property 5 cannot be sequenced apart" is wrong, and it rested on a false premise about the seek.

A snapshot is traversal events with a size-bound path index of {Path, Offset} beside them (snap/index.go), so ReadPathEventReader(kp) seeks to kp's offset -- or the nearest indexed ancestor, and streams forward -- inside a ROOT snapshot. The base read at any path is already bounded, by the substrate, doing what it was built to do. Nothing about all 246 snapshots being at the root makes the base unbounded.

What property 5 changes is TIME and INDEX SIZE, not the memory bound: how many patch records the compose step reads, which is the commits since the last snapshot (1,386 behind head here), shortened for hot paths by a snapshot nearer to them. Prerequisite 1 is within its bound on a store with root-only snapshots. Not fast there; still bounded.
