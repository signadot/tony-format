## measured while building DiffAbsolute

`!retag` belongs on this list too, for the same reason as the container case.

libdiff builds tag differences directly (`object.go`, `array_by_key.go`) and does not
take the option, so a `!retag(from,to)` still reaches an absolute diff. `!retag` is
checked -- `retagOp` refuses unless the document's tag already equals `from` -- so a
store cannot keep one.

The obvious repair does not work. `storableTags` says `addtag` and `rmtag` are the
unconditional halves of `retag`, so rewriting `!retag(a,b)` into `!rmtag(a).addtag(b)`
afterwards looks like it should be exact. Tried, over the property generator:

```
before the rewrite   6 of 500 round trips fail
after the rewrite   85 of 500 fail
```

So composing the two halves is not what applying `retag` does, and the difference is
not a detail. Reverted; `relativePrimitives` in `diff_absolute_property_test.go` names
`!replace`, `!strdiff` and `!arraydiff` and says why `!retag` is missing.

That makes this issue one thing rather than two: the vocabulary can state a
RELATION -- how a value differs from what was there -- and cannot state a RESULT,
for a container or for a tag. Whatever closes it has to give both.

## what does work today

`DiffAbsolute` handles `!replace`, `!strdiff` and `!arraydiff`, over all 500 seeds. An
object still diffs field by field and a keyed array element by element, so the cost is
paid only where a positional array or a string changed.

The lowering built on it (`lower.go`) is green for the cases it can reach: a scalar
`!replace` write is stored as its result, and the state matches the unlowered path.
