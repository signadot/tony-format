Decided (Scott), after a review of the branch: a read that cannot be answered exactly is answered at the **ceiling**, not the floor. This replaces "answered at the snapshot the read starts from" in the comments above.

## The rule

A read at `C` whose patches are partly compacted away is answered at the **oldest root snapshot at or after `C`** (the head, if there is none). That snapshot is what compaction kept in place of the commits in its chunk, so it holds `C`'s own write. The snapshot below `C` is missing everything between it and `C`, including `C` itself. The cost is that the ceiling also shows the writes between `C` and the snapshot.

The answered commit is then **at or after** the commit asked. A client's test is unchanged: answered differs from asked.

## Three changes to how it is decided

- **One rule, in storage, independent of the path.** A commit is exactly readable when the newest root snapshot at or below it is at it, or at or after the floor. Otherwise every read at it, at any path, is answered at the ceiling. The storage read applies the rule itself, so no read (an ancestor's, a watch's starting state) can fold across compacted patches. Path snapshots are not consulted: one could make a single path exact while its ancestors are not, and one commit answering differently by path is worse than an occasional approximate answer near the cutoff.
- **A floor that counts baseline patches only.** The replay floor also rises for dropped scope entries, so using it here answered exact baseline reads approximately. The read uses a separate floor that rises only when a baseline patch is dropped.
- **A set's cursor.** A continuation may repeat the commit first asked. A cursor whose commit is no longer exactly readable is `commit_not_found`, so the pages of one read never come from two states.

The not-found shape is as described above: the error carries the answered commit.

A watch whose starting state is not exact starts from the ceiling too (er3dnqpkh12krsb2qxn0).
