# analysis of the two remaining classes

## class A -- a !delete at a non-root path

**The head is right and the read is wrong, at the same commit.** Replaying the ops of
a failing seed against two stores, one keeping what the client sent and one keeping
lowered deltas, the stepped head and the store's OWN full read first disagree at
exactly the commit of the delete:

```
op 20  d.e <- !delete
  head: ... d: k0: 9 k1: nested: 16 k2: nested: 3 ...          <- deleted
  read: ... d: e: k1: 5 k0: 9 k1: nested: 16 ... ...           <- not deleted
```

So nothing is contaminated beforehand: the base the diff was taken against is the
state. The delta is what fails.

**The diff is right and the stored entry is wrong.** Diffing the two heads directly,
with the same options `lowerWrite` uses:

```
diff:    a: b: c: !comment ...   d: !insert k0: 9 k1: nested: 16 k2: nested: 3
stored:  a: b: c: !comment.logd-patch-root ...  d: k0: 9 k1: nested: 16 k2: nested: 3
```

`DiffAbsolute` answered `d: !insert {...}` -- a replacement of `d`, correct and
absolute, dropping `e`. What reached the log has the `!insert` GONE, so the replay
merges and `e` survives. Same at op 3, where the diff says `a: b: !delete {k2: 0}` and
the stored entry says `a: b: {k2: 0}`.

Note that the `!logd-patch-root` marker is missing from those nodes too, while the
`!comment` node next to them kept both its operation and its marker.

**What it is not.** Each of these was tried and measured:

- marker placement -- marking the delta's root instead of where the change lands
  makes it far worse, 19 value divergences against 4.
- comments in the diff -- turning `DiffComments` off makes it far worse, 21 against 5,
  because comment changes then vanish from the delta entirely.
- the payload under a `!delete` -- emptying it breaks index selectivity outright
  (`TestAbsentPathAnswersAsTheDocumentWould/verse.gone.zz`), because `IndexPatch` walks
  those paths to record what went away.
- the event stream -- `stream.NodeToEvents`/`EventsToNode` keeps an operation tag on a
  non-empty object, an array and a scalar alike. Checked all six shapes.

**Where it must be.** Between `lowerWrite` returning the delta and `dlog` holding it:
`markDeltaRoots`, `api.ValidateForStorage`, `dlog.NewEntry`, `AppendEntry`. The next
step is to print the delta at the point `lowerWrite` returns it and compare with what
comes back out of the log for that commit -- which of those four is the last to see
the tag.

## class B -- 20 snapshot-boundary cases

"the snapshot check dropped the head", with `error=<nil>`: the head disagrees with a
full read across a snapshot and is dropped rather than trusted.

Downstream of A, on the evidence available. Both failing tests are the same two
equivalence checks, the divergence check drops the head whenever a read disagrees with
it, and class A makes reads disagree. Stated as a hypothesis rather than a finding: it
has not been separated, and it should be re-counted once A is fixed rather than
analysed on its own.
