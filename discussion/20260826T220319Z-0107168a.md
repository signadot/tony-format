Confirmed: !get-path errors on a path which names nothing, !get-paths answers the empty
list. Each keeps the promise its name makes -- a node, or a list -- and the empty list is
the same reading !all over an empty container already has.

So the whole of it, settled:

  !get-path <kpath>     a wild path refused at Instance; a path naming nothing is an
                        error; the answer is one detached copy.
  !get-paths <kpath>    any path; a path naming nothing is the empty list; the answer is
                        a detached list of copies, each parented to the list.

  !get-path(root) ...   anchored at doc.Root(); the default anchor is the node the op
                        meets.  Args read by name, not position, so a later relaxation
                        param composes with or without the anchor.

  Patch installs the value (return V, nil).  Match hands it to f as an ordinary pattern --
  no implicit !raw, revisitable if a document ever carries an operator tag through a get.
  Reads see the input document throughout, so two gets which name each other are a swap.
