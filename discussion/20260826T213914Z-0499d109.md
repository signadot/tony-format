Question 2 is decided: the value is ALWAYS COPIED, on both sides. One rule rather than a
match side which keeps identity and a patch side which does not.

What that settles:

  - A node cannot belong to two trees. The patch side installs the answer in the result,
    and ir.FromSlice and the container builders re-parent what they are given, so the doc's
    own node would be spliced out of the document. A copy is what makes the answer
    installable.

  - A copy is a VALUE, not a place, which is the same reading !ir's child list now carries
    (264837c). The operator answers with what is over there, not with a second name for
    where it is.

  - The match side costs less than it looked. The produced node is used as the PATTERN --
    the op is handed the doc node at its own position and answers f(doc, value, ctx) -- and
    Explain takes its paths from the DOCUMENT side (pathOf is called on doc, at explain.go
    198 and 265), so a copy on the pattern side is not what a failure is reported against.

  - Clone() carries Parent across, so the copy has to be detached or re-parented where it
    lands rather than left pointing at the tree it came from. Whatever installs it owns
    that, the way FromSlice owns it for a list.
